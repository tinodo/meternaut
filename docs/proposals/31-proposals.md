# What a finding proposes: the settings to lower and the other ways to save — a decision record

**Status: decided on 2026-11-20. Built and tested against fakes: no model was called, nothing ran in Azure, and nothing is deployed.** This record is one of three pieces of the same work. It says what the Investigator may state beyond the change that code prices, and what code keeps of it. The family that lowers a setting after a person approved it, and the words of the page, the card and the letter, are the other two, and have their own records.

## What was asked

A finding already states its change in typed form: the action, the bill lines that it would shrink and what remains of them, and code prices it from the bill ([proposal 24](24-priced-findings.md)). What a person read was still a sentence of the AI ("lower the units from 4 to the base capacity") that code could neither check nor act on, with no other way to save named and nothing said of what each way gives up. A person who is asked needs to know what exactly would be set, from what to what, what it saves, what else could be done instead, and what each other way gives up. Meternaut has to find these ways by itself: nothing in an instruction, a tool or a document says how a resource is scaled, which tier or size exists, or what a kind of resource is called ([rule 30](../../AGENTS.md)). The Investigator reads the properties of a resource and the documentation about its type with the tools that exist, and states what it learned as data. Code checks the data.

## What the Investigator may state

Two optional entries of `change`, both data that code compares with what the tools showed in the same run:

- `set`: at most 3 settings, each `{"handle", "property", "from", "to"}`: a number that a tool showed for the resource, under the name that the tool gave it, for a property whose last key names a count or a size (see "Which property may be lowered"), and a smaller number. This is what a person can be asked to approve.
- `others`: at most 3 other ways to save on the same resource, each `{"title", "gives_up", "in_place", "change"}`. The title is at most 80 characters of letters, digits, spaces and the marks `, ( ) + -`, with no run of three digits, so that it holds no ordinary amount (digits with a currency or per-period words); an amount spelled in words, or around the check, still gets through, so the page marks every title as the AI's own words. `gives_up` is at most 240 characters on what the way costs in features, limits and availability, as far as the tools and the documentation that was read show it. `in_place` is true when the documentation says that the resource can be altered where it is, false when it says that it has to be made again, and left out when it says neither. `change` is a change of its own, in the same forms as the main one.

An invented example. The tools showed a resource of the invented kind `microsoft.example/gateways` with the property `capacityUnits` at 4, and its bill line costs 200 dollars a month. The Investigator states the main change `{"action": "reduce", "effects": [{"handle": "r1", "meters": ["m1"], "remains": {"form": "ratio", "on": "capacityUnits", "from": 4, "to": 2}}]}` and beside it `"set": [{"handle": "r1", "property": "capacityUnits", "from": 4, "to": 2}]` and `"others": [{"title": "Use the invented Lite tier", "gives_up": "Fewer units and no zone redundancy, as far as the pages say.", "in_place": false, "change": {"action": "switch", "effects": [...]}}]`. Nothing here is a kind, a property or a tier that an instruction names; the instructions say only what the entries are and how code treats them.

## What code keeps

Every entry is checked on its own. One that fails is dropped by itself, counted by the rule that it failed, and said in the notes of the run in plain words ("finding 2: code dropped 1 of 3 settings (a property that no tool showed: 1) and 1 of 2 other ways (a title that is not plain words: 1)"). The finding is never dropped for a bad entry: it opens its case as it always did.

| A setting is kept only when | |
|---|---|
| The finding proposes a change and its action is `reduce` | Any other proposal or action keeps no setting. |
| The handle is one of the finding's | Another resource, a handle that no tool showed and a handle that is not text are dropped. |
| The property is one that a tool showed for that handle, under that exact name, and the name is a plain one (`pricing.NAME`) | The properties are read from `Toolbox.evidence`, as the tools returned them. |
| Its value is one plain number | A word, a flag and a list (the value is a list when the items of a list under that key differ) are no number, and a setting on them is dropped. |
| The last key of the property names a count or a size (`proposals.countlike`) | A period, a version, a state, a code, a mode, a flag, the length of a list and a setting that decides how much is kept are no count: see "Which property may be lowered". |
| `from` is that number | The tools' number, within a millionth. |
| `to` is a number of the same kind, finite, not negative and smaller than `from` | Whole where `from` is whole. Only numbers that go down: a tier, a SKU or a flag is not a setting in this version. |
| The property is not listed twice for the resource, and no more than 3 are kept | The first ones are kept. |
| Where the change states a ratio on the same property of the same resource, `from` and `to` are its numbers | A setting that disagrees with the finding's own change is dropped. |

| Another way is kept only when | |
|---|---|
| The finding covers one resource | The ways of a finding of several resources are dropped and counted: a way is priced for one resource. |
| The title is plain words, at most 80 characters | Letters, digits, spaces and the marks `, ( ) + -`; no slash and no run of three digits, so a title holds no ordinary amount ("Saves 500/month", "Save 1200"); no link, markup or amount of money either: the same check as the other short phrases of an answer (`roles.clean_text`). An amount that is spelled in words or around the check still gets through, so the page marks every title as the AI's own words. |
| Its change has an action that code can read, and neither it nor its title repeats the main change or a way kept before it | An action none, an unknown action or a missing change is dropped, and so is a repeat. |
| No more than 3 are kept | |

A way is priced exactly as the main change is (`pricing.price`, for the finding's resource), from the bill, with the low and the high end of a month. A way that cannot be priced is kept with no figure, and the page says that it is not priced. A figure is kept for every form of the way's change, and the entry says whose it is: an estimate is a way whose remaining share is the AI's word; the page says so. The stored way carries `"estimate": true` only when its row has the form `assumed`, a share that only the AI states (the form `mixed`, which a resource gets when two of its meters are priced by different forms, counts the same, so as to say too much and never too little; so does a switch whose effect says `none` for a charge, the new price having no counterpart for it, which is read as an assumed share with nothing remaining, [proposal 28](28-alternative-prices.md#a-list-that-serves-every-meter-that-shares-it-and-a-charge-that-the-other-price-does-not-have-2026-11-21)), and the Skeptic is shown the same word; a way priced by a quantity, a ratio, an alternative, some days of every so many or a removal is not one: the days of a schedule are the AI's proposal, like a chosen quantity, not an assumed remainder. This is not the list-price estimate of a resource that has no cost line (`cases/estimate.py`). `gives_up` is cut and cleaned like the other words of the AI, and is kept as the AI's own words that code did not check: a person reads it marked so. A way never becomes a setting: nothing of what it says is executable.

## Which property may be lowered

A setting lowers a count or a size of what the resource holds, and nothing else: a lower period, version, state or flag is not a smaller amount of anything, and this version asks no person to approve one. `proposals.countlike(path)` is the one gate, a public function of the dotted path whose last key decides, for the check here and for the family that makes the change, which applies the very same function at plan time. The last key must rank in the toolbox's own `COUNT_LIKE` (`toolbox._rank`, which is what the toolbox orders its properties by: a key that ends in capacity, count, replicas, size, GB, cores, throughput, unit, units, Mbps or Gbps) or be a `numberOf…` key, and a `numberOf…` key that ends in a period (days, hours, minutes, seconds, weeks, months or years) is a period of time and not a count of what the resource holds. The path must be plain ASCII (the function checks the whole path, and the last key must be a plain name, as `pricing.NAME` says), so that a letter of another alphabet cannot pass for a count; the function is pure and answers False, never raises, for anything that is not a path. The toolbox's list of suffixes is neither widened nor copied (its hash is in the lock). One more refusal is needed because the toolbox makes up the length of a list as `<key of the list>Count`, which ranks as a count: a key that ends in a plural and `Count` is a list's length and is refused. That test is on the form of the name, so a real property that the platform names with a plural and `Count` is refused too, and a length that is made up under a key that is not a plural passes. One more refusal covers what a lower number deletes: a retention, a backup, a snapshot, a time to live, what to keep, a history, a version, a restore or recovery point, an archive, a purge, a revision, a checkpoint, a soft delete or a log file is held in counts and sizes that carry no period word (`retentionCount`, `retentionSizeGB`, `numberOfDaysToKeep`, `keepCount`, `backupCount`, `snapshotCount`, `maxHistoryCount`, `maxVersionCount`, `restorePointCount`, `archiveCount`, `purgeCount`, `recoveryPointCount`, `revisionCount`, `checkpointCount`, `softDeleteCount`, `logFileCount`, `purgingCount`, `deleteRetentionCount`), so a path that contains one of the words `retention`, `retain`, `retained`, `keep`, `kept`, `ttl`, `backup`, `snapshot`, `history`, `version`, `restore`, `archive`, `purg`, `recover`, `revision`, `checkpoint`, `softdelete`, `delete` or `logfile` anywhere, in any case and inside another word too (the tuple `KEPT_WORDS` in `cases/proposals.py`; `keepcount`, `BACKUPCOUNT`, `retentionpolicy.count` and `numberOfSnapShots` are refused as `keepCount` is), is refused too, with its own words: "a setting that decides how much is kept, which a lower number deletes". The test is on the letters of the whole lower-cased path and not on the words of a name, because a name that is written in one case, or that joins its words in its own way, would pass a test on words. So it also refuses a name that merely contains one of the words: `maxThrottleCount` holds `ttl`, and a keep-alive count holds `keep`. A refusal costs a request that nobody makes, and a lower number that deletes costs what was kept: over-refusal is the safe side. The list is not complete, as no list of words is: the confirm page that every real change shows, the undo sentence (setting the number back does not bring back what the lower number cut off) and the approver's own reading of the plan are the other guards. A refused setting is dropped by its own rule and said in the notes of the run in plain words ("a property that is not a count or a size", "a period, not a count or a size" or the words above). The gate is code: no instruction, tool or schema names a property (rule 30).

## What lands in the case

The kept entries are the typed facts of the case of each resource, under the key `ways`: `{"set": [{"path", "from", "to"}], "others": [{"title", "givesUp", "action", "inPlace", "lowUsd", "highUsd", "estimate"}]}` (`estimate` only when it is true), the shape that `cases/proposals.py` documents and reads back (`Other.estimate` is False for any stored value that is not the flag true). The shared module first named the key `proposal`, which the facts of a case already use for the word of the finding's proposal (delete, change, investigate) and which other parts read, so the key is `ways`. The facts are kept while a request that was asked with the price is still open and the finding is judged again with no price, as the price itself is; a case that a later answer makes with its own entries keeps those. The case of a group of resources keeps none, because a setting is a number of one resource, and that holds when a group is judged again as it does when it is made.

## What the Skeptic sees

The Skeptic is shown the kept settings (the handle, the property as the tool showed it, the value now and after) and the kept ways (title, what each gives up, the action, whether the resource can be altered where it is, what code priced it at, and `estimate` when that figure is an estimate) as typed data beside the model of the saving. A resource that is left out of what the Skeptic is shown has none of its entries in it. One general sentence tells it to judge whether the new value is safe given the evidence rows and whether what the ways give up is right, and to say disagree or unsure when it is not; one clause says what `estimate` means, that the figure of a way marked so rests on a share that the Investigator assumed. It can only make a finding weaker ([rule 30](../../AGENTS.md)).

## The instructions

The Investigator is told the shape and general principles, and nothing else: when the change is a smaller number for a property that a tool showed, state it inside the change too, because only a setting that is stated there can be approved and made ([rule 29](../../AGENTS.md)), and name nothing that the tools did not show; for a finding of one resource, list in `others`, inside the change as well, every other way that it found (a misplaced entry is not read), with a title made of letters, digits, spaces and the marks `, ( ) + -` and no run of three digits; learn the smaller options from the properties and from what the documentation was read to say, never only from what it already knows; and leave `in_place` out when the documentation says neither. A test scans the instructions for kinds of resource, measurements and thresholds, and the tests of this piece use invented kinds, properties and values only. The instructions grew from 10,878 to 11,983 characters (a test keeps them under 12,200). The Skeptic's instruction says in one clause that a way marked `estimate` has a figure that rests on a share that the Investigator assumed. The lock of the agents and the red team's copy of the instructions are written again, and only the two instruction hashes moved.

## The Study reads the kinds of an open finding first

What the documentation says about a type has to be on record before the Investigator judges a resource of it. The survey of the Study ranked the kinds of resource of the estate by their cost. It now puts first the kinds that a finding which nobody decided is about, and the kinds of a request that waits for an answer, read from the store of the loop with no text of the estate, and then the dearest kinds as before; the cap on the number of kinds is applied after that order. A kind that has a current claim, or a mark that it was studied, still does not wait.

## Text proposed for a rule of AGENTS.md

*The orchestrator numbers it, joins it with the text of the piece that makes the change, and adds it at the merge.*

> **The AI proposes what to change, code checks it, and a person makes it with their own rights** (2026-11-20, the owner, about a request that said "reduce" and nothing else, and a bill that showed what could be saved: "I WANT TO BE ABLE TO DO IT!"). Beside the change that code prices, the Investigator may state the settings that it would lower (a count or a size that a tool showed, the value now and a smaller value) and the other ways to save on the same resource (a title, what each gives up, whether the resource can be altered where it is, and a change of its own that code prices from the bill). Code keeps an entry only when it can compare it with what the tools showed in the same run, drops the others one by one and says so, and no figure is written by an AI (rule 30 (b)); what a way gives up is shown as the AI's own words. A kept setting is data: it is made only by the family that lowers a setting, after a named person approved it, with that person's own token (rule 29), in a resource group that the owner lists in `REAL_CHANGE_SCOPES`, and only while `REAL_CHANGES_ALLOWED` in `families/gates.py` is true; only the owner changes that line, in a pull request that he reads himself. `CHANGE_REQUIRES_PLANTED_TAG` and `CHANGE_SCOPES` stay as they are: every older family is held to what Meternaut planted itself. No instruction, tool, schema or document names how to scale anything, or a kind, a property, a limit or an option of a service (rule 30 (a)).

## The range that Microsoft's reference page gives for a number (2026-11-21)

**Why.** A replay of the Investigator on the invented row of a host with four units (Hub run 44873416016) stated a setting that lowers the units from 4 to 1. The reference page of that type gives a lowest number for that property, and 1 is below it. A request would have told the owner "lower from 4 to 1", priced a saving for a number that Azure refuses, and failed at the write. Nothing in the app knew what a property accepts, and nothing may be told per kind ([rule 30](../../AGENTS.md)).

**What is read, and from where.** The reference page of every resource type (`https://learn.microsoft.com/en-us/azure/templates/<the type in lower case>`, the address that the Study already reads) lists the properties of the type in tables of Name, Description and Value. A number that has bounds says so in its Value cell: `int`, `Constraints:`, `Min value = N`, `Max value = M`. `cases/ranges.py` reads those cells, for any type, and names no kind, property or number. It takes whole numbers only (2.5, 1,000 and 1e3 are not read), a bound alone is a range, and it ignores the rest of a cell (a length, a pattern, a list of words). A name that two rows of the page bound differently, or that one row bounds and another does not, has no range, because the table does not say which object the name belongs to. The page gives its tables three times (Bicep, JSON and Terraform): a name that all its rows bound alike has its range. Only the last key of a property is compared with the name: that is all the table gives.

**How often there is anything to show.** Seldom, and that is the common path. An independent review of this work measured it on 169 live reference pages (2026-11-21, read only): a range of any kind exists for 27 of 61 common types; a range for a count or a size, the only kind that the tools show, exists for 11 of 61 common types and for 6 of 160 random types; one with a lowest above 0, the only kind that can refuse a smaller number, exists for 6 of 61 common types, a few of them kinds that matter to an estate. For most types, then, the tools show no limits and the check refuses nothing: what the Investigator does when none are shown is the path that matters most (the instruction below and the row `lightly-used-bastion-without-limits`).

**How it reaches the Investigator.** The reader uses the docs client of the Study (`http.docs_calls`: GET only, no token, pages of Microsoft's documentation only; `Services.docs`) and reads the page of a type once in a run. It answers "not read" (which is never "no range") for an address that the Study may not read, a call that failed or was refused, a page that took more than 8 seconds, a run that has used 30 seconds or 24 pages of reading, a page of more than 2,000,000 bytes and a page with no table of property values. For a count or a size among the properties that `list_resources` (one mapping for the whole table), `describe` and `profile` show, the answer holds `limits`: for the property, by its key path, `{"lowest": N, "highest": M}`, and a bound that the page does not give is left out. A property with no entry has no range that was read, which is not the same as none. When a page was not read, the answer says nothing, and the investigation says one note of the run when it ends, with how many kinds of resource had no page read (a note for each kind would be as many as the kinds, and the run keeps 20 of its notes). The same limits are kept in the evidence of the handle, next to its properties, and the toolbox's module and the new module are in the digest that the lock holds.

**What code does with it.** A `set` whose new number is below the lowest or above the highest of the handle's limits is dropped like any entry that fails a rule, and the finding stays. The note of the run says it in plain words and gives the number that the page gives: "finding 1: code dropped 1 of 1 setting (a new value below N, the lowest that Microsoft's reference page gives for the setting: 1)". Code never repairs it: no setting with the lowest number is made of a number below it. Two things are held back with it. A ratio that the change states on that property is refused by the same range. And when a setting of a resource was refused for its range, no figure is worked out for that resource, whatever form the AI stated it in (a ratio, the quantity of a meter or a share that it assumes), because the number that the AI proposes for it is one that the platform does not take and its figure may rest on the same number: the request then says "No saving was worked out, because the number that the AI proposes is outside the range that Microsoft's reference page gives for the setting", the Skeptic is shown that word in place of the figure, and the request has neither the setting nor a figure for it. What is not held back, because nothing reads it for a number: the AI's own words (`how`, which the page shows as the AI's words), a quantity or an assumed share that the AI states for a resource that has no setting, and a setting that no page bounds. They can still name a number that the platform refuses, and the person and the Skeptic see them as the AI's own words. A figure of a number that is inside the range says so in one sentence with both numbers, on the page, the card and the letter (the figure of a group of resources says nothing of a range). With no limits for the property nothing changes. The Skeptic sees the range beside the numbers of the figure.

**What the Investigator is told.** One principle, in the paragraph about `set`: a number in a setting lies within the limits that an answer shows for that property; where none are shown it may still state the setting, and then it says in `how` that no tool showed the lowest number that the platform takes, and nothing more about it. No kind, property or number is named, and a test scans for them. The first wording said that where none are shown the lowest number "is not known to you", and an independent review found that it could read as "no limits, no setting", which is untrue when `recall_knowledge` holds a claim about the limit, and which would have applied to most types. The instructions grew from 11,983 to 12,232 characters (a test keeps them under 12,300); the lock and the red team's copy of the instructions are written again. The three tools say what `limits` is in their descriptions, in words that name nothing.

**In the evaluation.** The row of the lightly used host has the lowest and highest numbers that the page gives in its new optional field `limits`, per handle and property. The invented tools show them where and as the real ones do, a test holds each tool to the real toolbox on the same data, and the grader asks the app's own check with the limits that the replay's tools showed: an answer that states a number below the lowest is not found any more, and one that states the lowest or more is. A second row, `lightly-used-bastion-without-limits`, is the same host with no `limits`, which is the common path: the grader cannot refuse a number there, so it finds any smaller number, and a replay shows what the Investigator does when no limits are shown, whether it states the setting and what it says in `how`.

**What this proves and what not.** It proves that a number outside the range that the page gave is refused, with the figure of its resource, and that one inside is not refused for that. It does not prove that the platform takes a number inside the range: the range is the one of the API and not the one of a SKU or a plan, which may take fewer; a page can be wrong or late; a name that a page gives twice with two ranges is not read; and a name that the page bounds for another object of the type than the property that the tool showed would get a range that is not its own (the table gives no way to tell, and the number is then refused or kept on a range that does not apply). It does not read free text: a number in the AI's own words, or in a quantity or a share that no setting goes with, is not held to any range. And for most types nothing is shown and nothing is refused. A refusal is safe: the finding stays and a person is asked about it, and a wrong refusal costs a setting that nobody is asked to approve.

## What is not proved

- **That the Investigator states `set` and `others` well.** The first real run on this code (2026-11-21: 17 tool calls, 417,497 tokens) stated neither. Of its 9 findings 8 asked for a look and 1 proposed a deletion, and the three SQL databases, the only resources of the estate with a count of units above one, were judged "look at it", so no resource that it could back with a measurement offered a setting. The tool for the price list failed on 8 of its 9 calls (429 and a timeout), so no other way could be priced from the list. A run on a resource of that kind has to show whether it names the right property, whether it finds the smaller options in the documentation, whether it prices each way through a form that code accepts, and whether `gives_up` is true. Since 2026-11-21 an evaluation scenario measures the ability on an invented estate, for cents: three fixtures of a kind with a count of units, one that nobody uses (a good answer removes it), one that a few use (a good answer states a smaller count) and one that many use (a good answer states none), and, since the limits of a number, a fourth that is the one that a few use again with no limits shown, replayed through the real Investigator and graded by these checks ([the evaluation](11-agent-harness-and-evaluation.md#settings-and-other-ways-on-an-invented-estate-2026-11-21)). The first replay (the first and the last of them, on the same day) showed that the Investigator removes the host that nobody uses and states no setting for it, as its instructions say; the ability to state a setting has not been asked of it yet, and an invented estate says nothing of a real one.
- **That the Investigator finds and prices the other ways of an oversized host.** Since 2026-11-21 the row `bastion-four-units-full-story` of the evaluation gives such a host the bill, the price list and the documentation that the real tools would show, expects at least one other way that code keeps (`othersFoundRate`, a starting value) and prints what the app would show as the saving of the setting and of each other way ([the evaluation](11-agent-harness-and-evaluation.md#the-whole-story-of-an-oversized-host-on-an-invented-estate-2026-11-21)). No replay was run on it. The invented bill has the real list prices of one day and bill words that no bill gave, a switch to the free tier can only be priced as a share that the answer assumes, and the form that an answer picks decides the figure (a quantity of the charge that follows the units gives the saving, a ratio of the count on another meter does not), which code cannot tell. A second row, `bastion-four-units-floor-in-docs`, is the same host with no limits and no bill, and with the one sentence of the documentation that says the lowest count (so that only the documentation can say it), and finds the setting only at that floor or above it (`expect.set_floor`).
- **That the documentation of a type is on record before the Investigator judges a resource of it.** The Study runs weekly and reads at most eight kinds by default, so a kind with an open finding may wait a week, and a resource that no earlier run opened a finding for is judged with nothing on record unless the kind was studied for another reason.
- **That the property that a tool named is the one that a write changes.** The tools show a property under the path that the platform lists for the type; the family that makes the change reads the resource live, and says so when it is not a plain value of the resource. No write was tried.
- **That `gives_up` and `in_place` are right.** They are the Investigator's claims, not checked by any code, and the page says so. The Skeptic is told to doubt what a way gives up.
- **That a setting and the saving agree.** Code checks a setting against a ratio on the same property, and nothing ties it to a stated quantity of a meter, or a way's saving to what a person would see after the change; each saving is the bill's arithmetic on what the AI stated.
- **The page.** The Details table of the request page lists every typed fact except `ways`: the page says them in its own words (the question, the figure and the table of other ways), so the table leaves them out (`brief.PROPOSED` is the key), and `proposal`, the finding's own word (change, delete, investigate), is listed where it always was. A test of the whole chain holds both.
- **What reads of the real estate showed (read only, property names and counts only).** In the app's typed form the plans of one service showed `sku.capacity`, `numberOfWorkers` and counts as plain numbers, and a network gateway and an API management instance showed `sku.capacity` (2 and 1). An earlier version of the check kept a setting that lowered `sku.capacity` by one and dropped one that lowered a 0 to 0. No resource of the kind that the owner's example is about exists in the ten subscriptions that these reads could see, so the property of that example was not read. A later read ran the count gate over every number that the tools showed: 265 distinct last keys, of which it accepts 54 and refuses 211, 198 of them lengths of lists (`<plural>Count`) and 13 periods and versions; no genuine count was refused. The 54 include about 20 lengths that are made up under a key that is not a plural, which the name cannot tell from a real count (the family's live read of the resource stops those), and counts that no bill follows (of attempts, of probes, of tolerated failures): the gate says that a number is a count, not that the bill follows it, which is the price's rule (a ratio on a property is right only when the bill follows it), the Skeptic's and the person's to judge. A count whose key ends in none of the toolbox's suffixes, or that the platform does not list for the type, is not shown by the tools, so it never reaches the gate and a setting for it is dropped as "a property that no tool showed"; widening the toolbox's list is a decision for the toolbox and its own tests.
- **An entry stated outside `change`.** `set` and `others` are read from the change only, and a misplaced entry is not read and not counted: the instruction says where they go, and nothing else says so.
- **The package.** The sources that the Operator receives grew by 2,423 bytes on an LF copy (the archive from 321,122 to 323,545, the request from 357,501 to 359,924), which leaves 120,076 of the 480,000 free, 76 above the floor of 120,000. A run of the measure varies by about 80 bytes.
- **That the Investigator now states a number inside the range.** No replay was run on this code. A replay of the row of the lightly used host shows whether it states a number that the limits allow once it sees them. A replay of the row without limits shows what it does where none are shown (the common path): whether it states the setting at all, and whether it says in `how` that no tool showed the lowest number and nothing more. Until then the refusal is only a net under its answer, and a request whose setting was dropped asks for a look.

- **That the app's network lets the documentation pages through.** The investigation reads them with the same client and list of calls as the Study; whether the network of the function app allows them is what the first run of either says, and none was made here.
- **The figure of a group and the words of a real change.** The sentence that says a number is inside the range is made for the figure of one resource; the figure of a group of resources, and the words of the family that makes a change, say nothing of a range, because they do not hold it. A figure is held back for the resource whose setting the range refused, in a group too, and for no other.
- **Free text.** The AI's own words (`how`) and a quantity or a share that no setting goes with are not read for numbers, so a number that the platform refuses can still stand in them. A refusal of free text is not built: nothing in a sentence says which number is a setting's. The resource whose setting was refused loses its figure, and the person and the Skeptic see the words as the AI's own.
