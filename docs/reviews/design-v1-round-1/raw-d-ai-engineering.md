# Round 1 - lens D (AI engineering, evaluation and drift) - raw report

> Reviewed at commit `20390d4` · model `gpt-6-sol` · saved as returned by the reviewer (this header added). Orchestrator spot-checks and the disposition of every finding: [disposition.md](disposition.md).

## 1. Verdict in five lines

1. **Conditionally sound architecture, not yet a sound autonomy credential:** the read-only agent society and deterministic execution boundary are worth keeping.
2. **Must change:** make the Exam statistically defensible and bind every gate and credential to the exact *running* agent, evidence, domain and release.
3. Keep the spine for authorisation and budgets, but let investigations branch over immutable, provenance-bearing evidence; a typed record is not an injection firewall.
4. Foundry hosted agents and Agent Framework core fit; preview evaluation and safety features must be supplementary, not silent prerequisites.
5. Assumption: one EU-tenant self-hosted deployment, no controls deployed yet. Product citations below are vendor pages fetched for this review on 31 October 2026; untested integration is **UNVERIFIED**.

## 2. Findings

**D-01 · Major · File and heading:** `<repo>\docs\design\05-agents-and-orchestration.md`, §1, *The pattern: a deterministic spine with agentic leaves* · **Quote (verbatim):** “There is no agent-to-agent message channel, so there is nothing for an injected instruction to travel along.” · **Why it matters:** Case notes, retrieved claims and human objections *are* another agent's untrusted text. A rigid Detective→Skeptic→Economist graph also truncates competing hypotheses, negative results and unexpected experiments; repeatedly re-reading a mutable case increases tokens, latency and inconsistent conclusions. **Fix:** retain the deterministic approval/budget spine, but use an immutable, versioned evidence graph with receipt IDs, contrary evidence, epistemic uncertainty and bounded branch/return transitions; prohibit promotion of text to tool authority. Ablate the flexible versus fixed investigation on rediscovery, transfer, injection, tokens and latency. Agent Framework supports graph workflows that “branch on conditions, fan out to parallel steps, and converge results” ([Microsoft](https://devblogs.microsoft.com/agent-framework/microsoft-agent-framework-version-1-0/)).

**D-02 · Major · File and heading:** `<repo>\docs\design\05-agents-and-orchestration.md`, §2, *The roster* · **Quote (verbatim):** “Fourteen agents, deployed as **hosted agents** in Foundry Agent Service, in nine groups.” · **Why it matters:** The roster contains **15 hosted instances**: 14 logical roles, with two independently deployed Librarians. Identity, versions, tests, quota and cost must count instances. More importantly the Forger uses `acia-reason`, also used by investigators: contract/key separation prevents key sharing, not correlated generated traps or shared methodological blind spots. **Fix:** reconcile every roster, manifest, budget and test to 15 instances; pre-register which roles justify dedicated hosting, and test Forger/investigator independence empirically with different generators and externally labelled cases. Hosted Agent Service “assigns a dedicated Microsoft Entra ID (agent identity)” per deployed agent ([Microsoft](https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/hosted-agents)).

**D-03 · Critical · File and heading:** `<repo>\docs\design\07-security-architecture.md`, §5, *Defence against prompt injection in nine layers* · **Quote (verbatim):** “the only route for untrusted text” · **Why it matters:** Estate tags, names, cost-query results and Teams replies enter through other tools; calling the Document reader the only door leaves those routes unclassified. The proposed structured hosted-agent invocation does not specify a protocol-specific moderation mapping. On Invocations, a policy without `invocations_moderation` is inert; agent tool-response screening does not cover MCP. This can make G2 green while actual untrusted inputs pass unscreened. **Fix:** taint and bound *every* tool result at its source, test the actual deployed protocol and text paths (including missing/invalid policy), and enforce the deterministic tool gate independently of model moderation. Vendor: “On the `invocations` protocol, a policy attached without `invocations_moderation` is inert.” ([Microsoft](https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/add-hosted-agent-guardrails)); “Tool call and tool response intervention points require moderation support from the tool itself.” ([Microsoft](https://learn.microsoft.com/en-us/azure/foundry/guardrails/intervention-points)).

**D-04 · Major · File and heading:** `<repo>\docs\design\05-agents-and-orchestration.md`, §4, *How the spine runs* · **Quote (verbatim):** “state is JSON only, integrity-protected, and **only the spine's identity can read or write it**” · **Why it matters:** A custom serializer is promised but not specified; Agent Framework's built-in Python checkpoint stores “use Python's [`pickle`](https://docs.python.org/3/library/pickle.html) module to serialize non-JSON-native state” ([Microsoft](https://learn.microsoft.com/en-us/agent-framework/workflows/checkpoints)). Checkpoints occur at superstep boundaries, not atomically with queue acknowledgements, agent writes or Move effects. A 100-restart spike cannot establish no duplicated or lost side effects. **Fix:** specify JSON-only allowed types and schema migration, an inbox/outbox, lease fencing and idempotent externally visible effects; fault-inject every boundary. Compare the custom Container Apps spine **also with GA Durable Functions**, not only the prerelease Agent Framework Durable Extension: its runtime “manages state, checkpoints, retries, and recovery” ([Microsoft](https://learn.microsoft.com/en-us/azure/durable-task/durable-functions/durable-functions-overview)).

**D-05 · Major · File and heading:** `<repo>\docs\design\10-test-and-evaluation.md`, §4, *Release gates* · **Quote (verbatim):** “the lower bound of the interval falls below the baseline's or below the previous release's by more than a margin” · **Why it matters:** Comparing *two lower bounds* is not a test of the **paired difference**; it can admit a worse candidate. G2's attack resistance and G3's zero observed harmful decoys have no sample size, confidence level or acceptable population-risk bound. Even 0 harms in 100 independent decoys leaves a roughly 2.95% one-sided 95% upper bound; correlated generated estates are weaker. **Fix:** pre-register strata, power, non-inferiority margins and paired/clustered intervals; test harm separately by severity, with exact upper bounds and a human-reviewed critical-case veto. Freeze baselines and account for repeated releases and multiple metrics.

**D-06 · Major · File and heading:** `<repo>\docs\design\10-test-and-evaluation.md`, §4, *Release gates* · **Quote (verbatim):** “calibration error above its limit; any claim without a receipt” · **Why it matters:** G5 checks receipt *presence*, not whether the quoted source entails the claim in its SKU/region/date or whether its price and causal prediction are current. Aggregate calibration can hide domain-specific failure; unscored and abstained cases bias it. §9 also conflates retirement of a Groundedness safety control with the still-listed Foundry **Groundedness evaluator**: it “Measures how grounded the response is in the retrieved context” ([Microsoft](https://learn.microsoft.com/en-us/azure/foundry/concepts/built-in-evaluators)). **Fix:** check entailment, receipt hash/freshness, commercial-versus-Lab scope and numeric tool provenance independently; score probability calibration by domain and scored-case coverage, with intervals. Retain a validated groundedness evaluator or equivalent independent human labels rather than treating receipt presence as truth.

**D-07 · Major · File and heading:** `<repo>\docs\design\10-test-and-evaluation.md`, §7, *Testing the tests* · **Quote (verbatim):** “before every credential exam: nothing the system may have seen resembles a question.” · **Why it matters:** Similarity auditing is not physical isolation: training misses enter the Agenda, public exams circulate, and real-estate cases can reach the same estate's production traces and Atlas. The Forger generating a key and the Examiner scoring it does not yield independent truth; two judges that agree can share a rubric error. A leaked question should **not** merely be down-weighted for a credential. **Fix:** separate generator, sealed keys, labels and access logs from agents/trace-to-training jobs; use post-freeze, estate-held-out cases with consent; exclude possibly seen items. Pre-register human-verified keys and disagreement adjudication; report performance per autonomy domain, not only pooled.

**D-08 · Major · File and heading:** `<repo>\docs\design\05-agents-and-orchestration.md`, §3, *The workflows* · **Quote (verbatim):** “consolidate the day: lessons, detector candidates, Atlas change proposals” · **Why it matters:** W7 is a summary job, not the north star's method-learning or dreaming experiment. The requirements' FR-G4 is traced to §11's release/version procedure, which says how to ship a change, not how it learns which source, investigative tactic, question or model to prefer. Without exploration, held-out ablations and a causal/outcome ledger it may optimise easy cases and become a rulebook. **Fix:** define a scoped, budgeted method-policy learner with protected exploration, pre-registered A/Bs and replay limitations; distinguish source reliability, action selection and counterfactual prediction; have humans review proposals and score gains against retrieval-only and expert-seed baselines.

**D-09 · Major · File and heading:** `<repo>\docs\design\10-test-and-evaluation.md`, §9, *Platform mapping* · **Quote (verbatim):** “cloud runs: Sweden Central and France Central in the EU” · **Why it matters:** Two Microsoft pages conflict: one lists cloud red teaming in France Central/Sweden Central ([concept](https://learn.microsoft.com/en-us/azure/foundry/concepts/ai-red-teaming-agent): “Cloud red teaming is currently available in the following regions: East US 2, France Central, Sweden Central, Switzerland West, and US North Central.”), while the [evaluation-region page](https://learn.microsoft.com/en-us/azure/foundry/concepts/evaluation-regions-limits-virtual-network) lists only East US 2/North Central US. **EU availability is UNVERIFIED**. The [monitor page](https://learn.microsoft.com/en-us/azure/foundry/observability/how-to/how-to-monitor-agents-dashboard) labels “Recurring evaluations (preview)”; [built-in evaluators](https://learn.microsoft.com/en-us/azure/foundry/concepts/built-in-evaluators) label “Custom evaluators (preview)”. **Fix:** make the self-hosted EU evaluation/trace sampler and PyRIT/ASSERT the mandatory G2–G5 path; preview cloud scans are optional until an EU endpoint, billing and residency are proven in a live non-production test.

**D-10 · Major · File and heading:** `<repo>\docs\design\09-safeguards-and-drift-controls.md`, §2.2, *Drift under us* · **Quote (verbatim):** “a **behavioural fingerprint** probe each day: a fixed set of prompts whose refusal rate, format adherence, arithmetic accuracy and length distribution are compared with the baseline” · **Why it matters:** A behavioural fingerprint is a useful *statistical smoke alarm*, not an attestation that weights, router members or harm rates stayed fixed. Daily fixed probes are learnable and low-powered for rare failures; `model` response metadata need not prove which router member handled a call (**UNVERIFIED** until traced). Microsoft says new router members “are added to this version over time without changing the version identifier” ([Microsoft](https://learn.microsoft.com/en-us/azure/foundry/openai/concepts/model-router)). **Fix:** record resolved deployment/member where available, freeze a pinned subset, run stratified repeated probes plus rotating hidden cases and change-point bounds; trigger full Exam on unexpected changes. Fail closed if model attribution or EU fallback is unproven.

**D-11 · Major · File and heading:** `<repo>\docs\design\09-safeguards-and-drift-controls.md`, §2.2, *Drift under us* · **Quote (verbatim):** “the claim is demoted to *stale* automatically and the Study workflow is triggered; lessons expire” · **Why it matters:** Demotion does not quarantine dependent Detectors, Moves, Briefs or in-flight cases. P/D/C coverage is *proposed*, not an already existing platform facility: infrastructure, identity, network and policy have specified P/D but only conditional repair; model and prompt/skill/tool have P with partial semantic D/C (tool-list hashes miss changed tool behaviour); knowledge and data/schema have P/D but lack downstream invalidation; behaviour and evaluation rely on sampled or preview D and manual C; cost throttles after detection; platform change is a human request; autonomy revokes on *observed* regret, and people-drift corrective action remains advisory. **Fix:** a signed dependency graph from claim/data/tool/evaluator/credential to every consumer; on invalidation block reliance and autonomy before a fresh Exam, then repair or roll back. Fault-inject each detector and each claimed automatic correction in a test estate.

**D-12 · Major · File and heading:** `<repo>\docs\design\05-agents-and-orchestration.md`, §7, *The token economy* · **Quote (verbatim):** “the prefix is written once per release, not per case.” · **Why it matters:** Prompt caching is temporary, not a release-long stored prefix: “A cached prefix remains eligible for reuse for at least 30 minutes, but the service might retain it longer.” ([Microsoft](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/prompt-caching)). Keys do not guarantee a hit; long multi-agent rereads, judge reruns and cache-write tokens can dominate small cases. Design 12 §7 omits people's evaluation/approval time although the north star's report card counts it; G6's average case budget hides tail and exam costs. **Fix:** measure per-case p50/p95/p99 and complete research/Exam/human cost per *verified* saving, cache hit/write/miss by alias and context length; require measured incremental value of each agent hop and preserve immutable evidence digests rather than re-reading.

**D-13 · Major · File and heading:** `<repo>\docs\design\10-test-and-evaluation.md`, §9, *Release gates, as pipeline stages* · **Quote (verbatim):** “the L6 drill report and its recovery times” · **Why it matters:** G7 consumes monthly drill evidence for weekly releases without an expiry or manifest link. G8 asks whether a control *shows evidence*, not whether the denied action is actually blocked. G1 says signed artefacts, while signed-image admission is explicitly only spike S-DEL-1. G9 is a human act, but the credential is not specified as bound to the exact running model/prompt/skill/tool/Atlas and calibration cohort. **Fix:** every gate emits signed, time-bounded evidence keyed to the candidate manifest and deployed digest; block promotion if admission or control-effect tests are missing. Bind G9 to domain, impact cap, scope, manifest and expiry; withdraw automatically on invalidating drift, low outcome coverage or guard failure, not just regret.

**D-14 · Major · File and heading:** `<repo>\docs\design\05-agents-and-orchestration.md`, §5, *Anatomy of a leaf* · **Quote (verbatim):** “Container Apps Sandboxes (preview) are the cheaper per-second option once proven, behind a switch” · **Why it matters:** The vendor's [release record](https://www.microsoft.com/releasecommunications/api/v2/azure/561262) says “Generally Available: Azure Container Apps Sandboxes” (September 2026), and [Learn](https://learn.microsoft.com/en-us/azure/container-apps/sandboxes-overview) says “You pay no CPU or memory fees when sandboxes are stopped.” The design's preview classification and ADR-37 revisit trigger are stale. Its *relative* price, EU-region support and no-identity/deny-egress configuration for **this** workload remain **UNVERIFIED**. **Fix:** correct the preview register, then benchmark GA Sandboxes against GA dynamic sessions on isolation, region, suspended/storage cost, egress denial, audit and latency; retain the proven safer/cheaper option rather than switching on status alone.

## 4. What is strong — keep

- A real distinction between read-only reasoning and deterministic execution, with approvals bound to a Move and target (`<repo>\docs\design\03-logical-architecture.md`, §3–4).
- Provenance-bearing, scoped, reviewed Atlas releases and a tenant-local Lesson Book rather than preview platform memory (`<repo>\docs\design\06-data-and-knowledge.md`, §2–3).
- Paper/Lab/real Terrarium tiers, decoys, separate credential exams and two named baselines (`<repo>\docs\design\10-test-and-evaluation.md`, §2–3); keep the structure, repair the inference.
- Pinned manifests, canaries and a preview register with fallbacks (`<repo>\docs\design\09-safeguards-and-drift-controls.md`, §2–5); label statistical alarms as alarms.

## 5. What is missing — five priorities

1. **An investigation evidence contract**: immutable contrary evidence, disagreement, hypothesis branching and measured context/latency tradeoffs (D-01).
2. **An exam protocol**: independent keys, sealed held-outs, human adjudication, domain sample sizes, paired baselines, harm upper bounds and selection-coverage reports (D-05–D-07).
3. **A proven durable spine**: compare GA Durable Functions, specify transactional side effects and validate versioned checkpoint rehydration (D-04).
4. **Causal invalidation through the dependency graph**: revoke downstream claims, detectors, Moves and scoped credentials when sources, models or evaluators drift (D-10–D-13).
5. **A genuinely closed learning loop**: pre-registered method experiments and protected exploration; fail-closed production tests for Invocations/MCP and EU preview fallbacks (D-03, D-08–D-09).
