# Decision review: the adversary (security, abuse, spoofing, privacy)

Reviewer lens: threat model of the experience layer. Sources: experience spec (draft 2), cards C1–C15, `tools/cardlint.py`, design `05` §6–7 and `06` §3–8 and §12. Today: 2026-11-02.

## 1. Verdict

The experience is right to refuse approval by prose, e-mail, voice or a hidden "yes", and the page shape (CSP, `frame-ancestors 'none'`, CSRF, no-store, system browser) is the correct place for R2 and R3. It is not safe to build yet. The one-tap path treats an 8-character plan code and an `Action.Submit` fallback as if they bound a person, a plan and a time, and an owner can teach the whole estate. I would not ship R1, C10, C11 or manager escalation until those are closed.

## 2. Top 5 changes I would make

**1. `Action.Submit` never approves.** C4 puts verb `ok` and `requestId` on both `Action.Execute` and its Submit fallback. The same pattern is on `undo`, `stop-here`, `widen`, `confirm` and `me`. Token exchange is documented for the Execute invoke, not for Submit, and a bot cannot return a replacement card for Submit. If the bot treats Submit as `ok`, the "approver comes from the tapper's token" rule (design `05` §6) is gone. Cost: old clients do R1 on the page (already the P3 fallback). `cardlint.py` must fail a mutating fallback verb.

**2. Bind the tap to the plan shown, and to that person.** The 8-character code is a prefix of the plan hash, printed on the card. Anyone who can see the card knows it. C4 does not send it back. A forwarded, shared or stale card is then approved as whoever taps, if the service only checks that the token is valid (design `06` §5 takes the approver *from* the token: authentication, not authorisation). Likely: high. Bad: a colleague changes someone else's non-production resources, inside an unnamed cap. Cost: echo the code; reject a mismatch, expiry, pause, or any tapper who is not the designated approver or a named delegate. Show the remaining cap on C4.

**3. Take "everywhere" off owner cards.** C10 defaults scope to `${proposedScope}` (a model can set it) and offers Everywhere. C11 is one tap, with no count of whose resources change. A Lesson must not widen a credential (design `06` §3) but a wrong Lesson still misdirects advice. A person who can write a tag, then tap "Yes, this is me" (C1), becomes owner of record (design `05` §5). Likely: medium. Bad: estate-wide silence. Cost: owners scope only to the resource. Wider scope is a page for a platform or FinOps hat, with the affected list. No model sets the default (spec §11 bans pre-ticked consent).

**4. Do not escalate silence to a manager.** Day 8 (spec §11) sends the case to "delegate, manager, custodian", so a line manager learns a named person did not answer. The Monday letter adds team counts and ages; in a team of three, counts identify people. Design `06` §7 says the system never ranks a person, and parks the works-council step on voice only. The ladder contradicts both. Likely: certain. Bad: the product becomes monitoring; a works council can stop it. Cost: chase via the desk and a custodian, after a person looks. No object id in the workbook feed (spec §10).

**5. Treat bound text as hostile, and pin the address people learn.** Teams renders markdown links in `TextBlock`, `Fact.Title` and `Fact.Value`. A resource named `[Approve this](https://evil.example)` becomes a link beside the real button. The number check (spec §19) does not catch an instruction or a link. The plan code does not authenticate the sender: a clone that copies the code matches a cloned page. A person can check a fixed host from the announcement, the installed app in a 1:1 chat (not a person, guest or other app), and an Entra sign-in with no consent prompt. Cost: strip markdown and URLs from bound fields; pin `pageUrl` to the configured origin; put the app id in the announcement. A consent screen means fraud.

## 4. Decisions I agree with, and why each might still be wrong

X4 (no approval by e-mail, text or voice): right, unless a reply can Teach. X5 and the page headers: right; a stolen session can still read the plan if step-up is only on the button. X16: right; the subject line undoes the minimum. X18: right; the manager ladder is a worse inference. X20: right only if the note is omitted server-side. X21: right; an audio file is voice by another door. X25: right; I did not re-fetch the web-view limitation. X13: right; extend it to R1.

## 5. What is missing entirely

A consent-phishing runbook (real Microsoft login, wrong client id). A "this was not me" action that revokes the approval and pauses that person's R1. Guest, external-tenant and look-alike-app handling. What "Not mine", "Fewer like this" and "Stop this here" do to other people's resources. Retention for replies and transcripts. A works-council gate on manager-visible signals, not only on voice. An origin allow-list at send time, not only in `cardlint.py`.

## 6. What I verified, and what I could not

Confirmed. Markdown hyperlinks in `TextBlock`: [Format cards](https://learn.microsoft.com/microsoftteams/platform/task-modules-and-cards/cards/cards-format#format-cards-with-markdown). Token exchange on the Execute invoke: [Enable SSO](https://learn.microsoft.com/microsoftteams/platform/task-modules-and-cards/cards/universal-actions-for-adaptive-cards/enable-sso-for-your-adaptive-cards-universal-action). Submit cannot return a new card: [backward compatibility](https://learn.microsoft.com/adaptive-cards/authoring-cards/universal-action-model#backward-compatibility). No sentence says Submit carries no Entra token; the downgrade follows from SSO being specified only for Execute. Default policy allows third-party and custom apps: [app permission policies](https://learn.microsoft.com/microsoftteams/teams-app-permission-policies). Contexts C1–C99 and the claims challenge need Entra ID P1 and user sign-in, not app-only tokens: [authentication context](https://learn.microsoft.com/entra/identity-platform/developer-guide-conditional-access-authentication-context). Disclose synthetic voices and avatars; avatar output is watermarked: [transparency note](https://learn.microsoft.com/azure/foundry/responsible-ai/speech-service/text-to-speech/transparency-note). Custom neural voice is Limited Access: [limited access](https://learn.microsoft.com/azure/foundry/responsible-ai/speech-service/text-to-speech/limited-access). Check runs are App-only; fork pushes return an empty `pull_requests` array: [create a check run](https://docs.github.com/en/rest/checks/runs#create-a-check-run).

Not verified. That Teams blocks a guest from the display name "Cost in Action (AI)". DMARC as seen by Graph `sendMail`. That an embedded web view breaks security keys (spec §9 cites R4). The Article 50 clause on EUR-Lex. A plain audio file being watermarked: what I read covers avatars and personal voice, not every summary.
