## Also changed

- **Which states are waited for.** While checking the fix of H2-14 against the reference, I found that it names no final state for an API ("The provisioning state"), so waiting for a state in a short list of final words would fail every run for a perfectly good object whose final state is spelled otherwise. The tool now waits only for states that clearly mean "working" (in progress, accepted, creating, updating and a few more, whatever their case), stops on failed or cancelled, and takes any other word as final. Tests cover an unknown final word, each working word and each bad word (`tools/apim-sync.py`, `tools/tests/test_apim_sync.py`).
- **Two patterns let a trailing newline through.** The pattern of the instance's id and the pattern of the smoke test's key were written `^...$` and used with `match`, and in Python `$` also matches before a final newline. The id would have been stopped by the address check in any case, but a pattern should be strict on its own: both use `fullmatch` now, with tests for a newline, a carriage return, a tab, a null and a non-ASCII letter at the end (`tools/apim-sync.py`, `tools/hub-smoke.py`).
- **The README's list of what has not been seen** now carries the reviewer's new points: that Azure accepts the principal-type condition, that the budget step reads the real date and the real not-found answer, that the typed expressions run in the instance, and that the large request crosses the contract's allowance without first meeting the model's own capacity (`hub/README.md`).
