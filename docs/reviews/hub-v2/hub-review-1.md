# Hub review 2: raw report

A reviewer on another model family (gpt-6.1-sol) read the rebuilt hub at commit `32399ac` of the branch `hub-existing-apim`: the workflow, the Bicep template, the gateway tool and its policies, the bootstrap, the three helper tools, their tests and the documents, against the rules and the facts about the landing zone that the brief gave. The review was read-only: the reviewer ran the tests and the Bicep compile locally and changed nothing in Azure or GitHub. The report is as delivered, except that the file paths were absolute and are shortened here to paths relative to the repository.

## Verdict

**No: commit 32399ac is not yet a safe, review-ready corrected hub package.** It correctly reuses the existing gateway and landing-zone DNS, but a reproducible URL-validation escape can turn removal of a Meternaut object into deletion of the existing APIM service, and several deployment, cleanup and verification guarantees are not implemented reliably.

## Verified right, to be kept

- **The template fixes the original resource-duplication mistakes.** Inspection of the compiled ARM confirmed no new APIM service, private DNS zone, VNet link, private-endpoint zone group, manual peering or route table. The subnet has an NSG, DNS servers are required, and model public access and local-key authentication are disabled.
- **Both Bicep templates compile and lint cleanly.** Bicep 0.46.1, `--stdout` and `--no-restore`; all four build and lint exit codes were zero. This validates Bicep structure, not APIM policy execution.
- **All 141 tool tests passed.** The reviewer used unittest discovery with fixture filesystem operations virtualised in memory, bytecode disabled, and real disk mutation and network access blocked. This respected the no-write requirement; it does not strengthen the stand-ins into service integration tests.
- **The current workflow trigger and identity wiring are consistent:** manual dispatch only, owner and main job guard, matching branch-based OIDC subject, serialised runs, pinned actions and checkout credentials disabled. The known inability to distinguish the owner from an agent using his login remains a process limitation; `GITHUB_ACTIONS=true` is only an accident guard, not authorisation.
- **The questioned Bash constructs behaved correctly in isolated probes** using the runner's shell flags: `present()` distinguishes not-found from authorisation failure, explicit fatal errors stop execution, a failed deploy remains visible inside `if`, a failed restore retry exits, and an empty flags array adds no argument. Key masking occurs before the smoke process receives the key.
- **The transport host fences and redirect refusals are sound independently of H2-01.** The ARM token is restricted to the management host; neither client follows redirects. The workflow does not place the smoke key in a command-line argument.
- **Other local checks passed:** strict documentation lint checked 119 documents with no findings; the workflow lint checked two workflows with no findings; the bootstrap PowerShell blocks parsed without errors; the cost-model self-tests passed. `--dev-hub` produced 6.42 euros for the endpoint and 1.06 euros for the monthly token quota at the stored prices.
- **No new non-fixture subscription or tenant GUIDs were found in the diff.** The GUID literals were built-in role identifiers or synthetic test fixtures. The tracked working tree remained clean, and no Azure or GitHub operations were performed.

## Not verified offline: the owner-started workflow has to prove these

- **Effective authorisation with the actual narrow deployment identity**, especially ARM what-if and soft-delete restoration. The reviewer found no explicit subscription-wide inventory or provider-registration call that would justify a missing-permission finding; privileged-owner testing would nevertheless not prove that the configured identity works.
- **Acceptance of the exact 2024-05-01 REST payloads and APIM policy expressions**, including the relative logger reference, product and API inheritance, managed-identity authentication and token metrics. The unit stand-ins do not validate these service contracts.
- **Real private connectivity and DNS readiness.** The wait observes a zone-group configuration containing a zone ID, not a completed DNS record or successful resolution from APIM. Network-manager convergence, DNS resolution and backend reachability still need end-to-end proof.
- **A complete lifecycle:** deploy, redeploy, pause, redeploy, remove, preview and restore, while preserving the shared instance's unrelated objects and policy-created and network-manager-created state.
- **Actual security and accounting behaviour:** rejection of other subscription scopes, malformed, duplicate and array model fields, streaming behaviour, limiter-origin identification, usable token counts, and absence of keys, prompts and answers from real telemetry.
- **Actual incremental running cost.** The price-snapshot calculation is not a bill and does not establish processed-data charges or any additional central logging or network-manager charges. Those exclusions need checking before treating the endpoint as the only incremental fixed cost.
