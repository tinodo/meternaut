## 1. Verdict

**Mostly.** The separation between deterministic Durable Functions orchestrations, stateless hosted agents behind a governance gateway, and a fail-closed execution plane is well-grounded in current Microsoft Learn documentation and credible to an Azure and FinOps engineer. However, the showcase Atlas YAML claim misstates Azure Blob versioning tier-billing rules relative to the exact Learn page it cites, and several contradictions around role isolation inside shared sandboxes, Lesson writes, and Autopilot state transitions should be fixed before publication.

## 4. Fact checks

1. **Claim (`03:21`):** `"Some flagship models need the Responses API for tool calls, as Learn says today of GPT-6.1 Sol"` — `https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/models-sold-directly-by-azure` — **Verified:** `gpt-6.1-sol (2026-09-29)` lists `"Functions, tools, and parallel tool calling (Responses API only)"`.
2. **Claim (`03:19, 25, 116`):** Hosted agent versions are immutable with no traffic split; session idle timeout is `2`–`240` minutes (default `15`); sessions expire after `30` idle days — `https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/hosted-agents` — **Verified** under *Versioning* and *Sessions / Scaling and right-sizing*.
3. **Claim (`03:114`):** `"In Python one timer is limited to six days, so a longer wait is a loop of shorter timers"` — `https://learn.microsoft.com/en-us/azure/durable-task/common/durable-task-timers` — **Verified** under *Durable timer limitations* (6-day limit for JS, Python, PowerShell; `while` loop workaround).
4. **Claim (`04:49-51, 63, 69`):** Quote `"You are billed for blob versions, like blob snapshots, at the same rate as active data."` and claim `"If a version's tier is set explicitly, its full length is billed"` / `"an explicit tier bills each version in full"` — `https://learn.microsoft.com/en-us/azure/storage/blobs/versioning-overview` — **Quote verified; rule incomplete/misstated (Finding #1):** explicitly tiering an object bills its full length **and** the oldest version in the original tier in full (other unmoved versions stay billed by unique blocks); Archive bills **all** versions and snapshots in full.
5. **Claim (`04:314`):** `"Cost data arrives within 8 to 24 hours, up to 72 on pay-as-you-go; the open month is an estimate, rerated until the invoice closes"` — `https://learn.microsoft.com/en-us/azure/cost-management-billing/costs/understand-cost-mgt-data` — **Verified** under *Cost and usage data updates and retention* and *Rerated data*.

## 5. Questions left unanswered

1. **How does `investigate` prevent cross-role state leakage when reusing a warm sandbox session (`03:12, 25`)?** One `session_id` shares `$HOME` and `/files` across untrusted-text roles (`Surveyor`, `Detective`) and structured-only roles (`Economist`, `Auditor`, `Conductor`).
2. **Which identity writes `Lessons` and predictions to Cosmos DB (`03:15, 70, 171`, `04:220, 226, 228`)?** Only `engineer` holds `ledger-propose`, yet workflows (`Respond`, `Case`) store Lessons and predictions before `engineer` runs.
3. **What defines a "workload" boundary in `price-sim` (`04:220`)?** How are resources partitioned into workloads without double-counting shared services (VNets, Log Analytics, ACR)?
4. **How does `Study` discover which Learn pages and REST specs to poll (`04:167-176`)?** Does it only watch URLs already in Atlas receipts, or crawl feeds/sitemaps to find new services on day zero?
5. **What happens if an owner clicks `Challenge` or `Teach` after an Action has executed (`03:70, 170-171`)?** Does `Respond` trigger a rollback or only store a Lesson for future Cases?
