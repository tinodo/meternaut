# Reviewer B: adversary and consistency

Basis: `spec.md` as supplied; `AGENTS.md`, design and experience documents from released `HEAD c182733`, not concurrent edits. Microsoft Learn links below were checked on 2026-11-02. This is a specification review, not a deployment result.

## Seven answers

1. **Order.** Finish the synthetic tool and component suite before deploying the first role. Start the mailbox and permission work in parallel, not after the Case. In 1a, a FinOps hunch or Advisor lead can exercise the first real Case while Detectors remain in shadow. Land cost data and the Estate model in parallel; measure explained spend only after their join. Add a thin pilot report-card/status view, a first *source-change* Study smoke test, a red-team run and an Operate kill-switch drill. Full Study, the learning comparison and the full report card still belong to 1b (`docs/design/13-roadmap.md:12-13`).

2. **Dependencies.** Slice 0.2 cannot finish C1 without the hosted agent (0.3) and published tool (0.4); 0.3 cannot deploy before its component suite (0.5). Slice 1a.1 promises stored profiles before Estate refresh (1a.3); 1a.2 promises explained spend before owners, purposes and mechanisms are joined. Slice 1a.4 cannot show a priced Recommendation before 1a.6. Slice 1a.5 cannot promote Detectors from source-verified rows alone. Slice 1a.7 calls an e-mail “first contact” before its identity/settings/opt-out page exists. Separate “can start” from “can pass its check,” and draw both dependencies.

3. **First checks.** P1/P2/P9 need a complete agent-tool call, failure recovery, *all* pin fields and a host-cost comparison, not just an hour's wait or one changed description. P4 needs Team/Enterprise load and an honest agreement/access coverage matrix; P7 needs enumerated attack paths, exfiltration and wallet tests; P10 needs fixed margins and cloud-bill reconciliation. P3/P8 belong later; P5/P6 are deliberately 1b, but 1a still needs a defined pilot release gate. C9 covers the Teams unknowns only if failed fallbacks are retested. C4 needs MIME received, a denied second mailbox and recipients, and human comprehension checks (`docs/experience/12-testing-the-experience.md:15-17,83-87`).

4. **Sizes.** The most optimistic is 1a.6: **12–18 person-weeks**, not 6–8, as a starting scenario. It includes a bounded, resumable Case workflow; three independently tested roles; mixed price bases and a deterministic simulator; tool/identity boundaries; and path-by-path adversarial tests. Its dependencies do not provide those implementations. Budget a separate hub-bootstrap scenario for adopters without a hub. The 1a.8 range is work effort, not the calendar time to get a FinOps answer or a closed bill. Re-estimate after integration and the first real Case, not only after 0.3.

5. **Monday blockers.** A named hub owner, permissions to bootstrap identities and the hub, model capacity, an estate with actual cost reach, a billing-data/export owner, M365/Exchange administration, a mailbox and allow-list, private DNS/network and a deploy runner are needed before the relevant slice. The security, privacy/retention and data-boundary decisions need owners; do not silently select Global processing or assume licences. Region has a default, but data boundary, hub route, runner route and eligible first estate do not (`spec.md:95-101`). A newly created subscription can take up to 48 hours before Cost Management features work ([Learn](https://learn.microsoft.com/azure/cost-management-billing/costs/tutorial-acm-create-budgets)).

6. **Contradictions.** “FOCUS” from any API (`spec.md:56`) conflicts with mapped non-FOCUS fallbacks (`docs/design/14-agreements-and-access.md:40-47`). “Verified” bank rows as promoted Detectors (`spec.md:59`) conflicts with confirmation, shadow and human promotion (`docs/design/04-knowledge-and-learning.md:242-268`; `docs/design/08-testing-and-evaluation.md:30`). First contact without a page (`spec.md:61,68`) conflicts with the identity/settings/opt-out flow (`docs/experience/05-letters-and-requests.md:103-109`). Omitting Operate endpoints (`spec.md:107`) conflicts with the deployed profile's eleven (`docs/design/02-architecture.md:135-145`). These are behavioral differences, not wording.

7. **Likely failures.** First, a broad mail-app grant or failed delivery compromises the only live channel: test effective mailbox access and actual receipt before prod. Second, insufficient bill access or aggregate-only cost data yields convincing but unpriced advice: choose a bill-readable first estate and label every gap. Third, premature Detectors and a shallow safety gate turn false positives into Monday mail: keep Detectors shadowed, require decoy and injection gates, then get human confirmation. None is cured by declaring a fallback in a table.

## Findings

1. **Blocker · `spec.md:30,45-49,80` ·** C1 is assigned to five empty apps, before an agent and tool exist. The role in 0.3 precedes the suite in 0.5, violating the specification's own gate; 0.2 also claims tools that 0.4 has not published. P1 therefore cannot pass at the claimed slice (`docs/design/13-roadmap.md:11,25`). **Fix:** make 0.2 infrastructure-only, create the stub and suite first, then deploy 0.3 and run C1/P1 across all three.

2. **Blocker · `spec.md:55-58` ·** The capability profile is stored by Estate refresh, built in 1a.3 (`docs/design/14-agreements-and-access.md:61`; `docs/design/04-knowledge-and-learning.md:270-272`). Explained spend requires an owner, purpose and billing mechanism, not merely a landed file (`docs/design/08-testing-and-evaluation.md:70`). 1a.4 also shows a Recommendation before its Case and simulator exist. **Fix:** let 1a.1 show raw probe evidence, 1a.2 show landing/reconciliation, and gate explained spend and the priced draft after 1a.3/1a.6.

3. **Blocker · `spec.md:56,84,99` ·** The claimed universal FOCUS/Cost Details/Query path is not a detailed bill path for all agreements. FOCUS exports exclude pay-as-you-go; Cost Details excludes it; Query gives aggregate query results; the supported detailed alternative is pay-as-you-go exports where available or Consumption Usage Details (`docs/design/14-agreements-and-access.md:40-47`). [Learn: exports](https://learn.microsoft.com/azure/cost-management-billing/costs/tutorial-improved-exports), [Cost Details](https://learn.microsoft.com/azure/cost-management-billing/automate/get-small-usage-datasets-on-demand), [pay-as-you-go](https://learn.microsoft.com/azure/cost-management-billing/automate/get-usage-details-legacy-customer), [Query](https://learn.microsoft.com/rest/api/cost-management/query/usage). **Fix:** specify source-by-access mappings, fidelity/completeness and “unknown”; require readable cost data for the 1a explained-spend exit. List-price-only is a different, non-passing pilot.

4. **Major · `spec.md:59` ·** An adjudicated “Verified” bank row verifies a documented mechanism, not a bill or a finding (`docs/design/08-testing-and-evaluation.md:28-32`). Design requires a confirmed Case, back-test, shadow record, human promotion and limits by domain (`docs/design/04-knowledge-and-learning.md:242-268`). **Fix:** make seed Detectors drafts/shadow leads; run the first Case from a human hunch or Advisor lead, and promote only against predeclared precision and decoy thresholds.

5. **Major · `spec.md:55-56,84-85` ·** C6 checks one estate, but P4 asks whether DuckDB and Cosmos hold at **Team and Enterprise** volume (`docs/design/13-roadmap.md:28`). C5 cannot prove an unseen agreement: no billing account or bill lines can leave the family unknown (`docs/design/14-agreements-and-access.md:63-67,144-149`). **Fix:** load-test both volumes with generated data in existing environments; name query, RU, refresh and cost bounds beforehand. Compare the same identity's portal reach on each pilot access path and record untested paths as unproven, not passed.

6. **Blocker · `spec.md:83,95` ·** “Exchange RBAC limits the app to one mailbox” is unsafe without specifying **RBAC-only** grants. Microsoft says an unscoped Entra `Mail.Send` permission and a scoped Exchange grant are additive; the former still permits other mailboxes ([Learn, RBAC FAQ](https://learn.microsoft.com/exchange/permissions-exo/application-rbac)). **Fix:** do not grant, or remove, the tenant-wide Entra mail permission; assign scoped Exchange application roles and test both allowed mailbox and denied second mailbox after permissions propagate. Recipient allow-list is a separate control.

7. **Major · `spec.md:49,61,83,68` ·** “Every one holds” does not define delivery, and C4's Teams/web fallback is not built until phase 2. Graph `202 Accepted` proves acceptance, not delivery ([Learn](https://learn.microsoft.com/graph/api/user-sendmail)). **Fix:** inspect received MIME and both headers in the test inbox, prove the recipient reject rule with an out-of-list address, test the real approved recipient and classic/new Outlook, and fail/hold 1a rather than pretend the future channel exists. Include a safe retry/unknown-delivery procedure.

8. **Major · `spec.md:61,68` ·** The first-contact e-mail requires an announcement, identity check, preferences and opt-out; the Monday letter links to a report card and shows learned, wrong, verified and unverified outcomes (`docs/experience/05-letters-and-requests.md:24-35,37-54,103-109`). The page, Study and report card arrive only in later phases (`docs/design/13-roadmap.md:12-14`). **Fix:** use an explicitly agreed internal FinOps pilot introduction, not the owner first-contact flow; provide a small truthful status/report-card view or label unavailable sections, and test the letter with cold readers before live use.

9. **Major · `spec.md:28,60,68,86` ·** P7 is nearly vacuous if no propose tool or Azure write role exists before phase 3. “A red team finds none” also has no bounded population. The released suite includes message/recipient, tool-scope, canary and denial-of-wallet attacks (`docs/design/06-security-and-governance.md:83-97`; `docs/design/08-testing-and-evaluation.md:105-116`). Its release gate also requires sealed baselines that the plan defers to 1b (`docs/design/08-testing-and-evaluation.md:164-174`). **Fix:** predeclare a path matrix and attack/decoy gates for 1a, repeat the propose/approval tests in phase 3, and reconcile the design's release gate explicitly; never waive it silently.

10. **Major · `spec.md:46-47,81-82` ·** A one-hour timer does not demonstrate backend recovery or comparative price (P2), and a changed description alone does not demonstrate pinning of name, schema, digest and optional host value (P9; `docs/design/13-roadmap.md:26,33`). In-line hub rejection is still unverified (`docs/design/07-safeguards-and-drift.md:72,152-157`). **Fix:** force workflow/agent failure and resume, compare both backends on measured recovery/cost, mutate each pin field, and measure optional MCP host cost or mark that part of P9 open.

11. **Blocker · `spec.md:51,60,62,87` ·** Reaching the pre-set count **or revising the plan** is not the roadmap exit: the count must actually be reached (`docs/design/13-roadmap.md:12,21`). C8 has no fixed margin or matched billing period; hub logs alone cannot account for the model's Function, Search, storage and network lines (`docs/design/10-cost-and-finops.md:54-83`). The first recipient is the FinOps lead, not necessarily a resource owner. **Fix:** pre-register count and tolerances; join token logs to billed infrastructure with an allocation rule, include dead ends and people-hours, name FinOps-only cases honestly, and record a failed exit as failed.

12. **Major · `spec.md:107` ·** The Pilot column is **not** an upper bound: it assumes five subscriptions/500 resources and seeded work, omits an adopter's deployment runner and the hub, and prices the full eleven-endpoint profile (`docs/design/10-cost-and-finops.md:7,20-26,115,125,146-155`; `docs/design/02-architecture.md:135-145`). Omitting `approvals`/`runner` endpoints while claiming the unchanged Operate profile is a topology contradiction. **Fix:** call Pilot a reference scenario; state profile variants explicitly, rerun the model for actual deployed components and volumes, and show separate hub/runner and licence exposure rather than assuming savings.

13. **Major · `spec.md:28,31,33,55,110` ·** “Kill switches exist” is not a readiness test. Budgets alert but do not stop consumption ([Learn](https://learn.microsoft.com/azure/cost-management-billing/costs/tutorial-acm-create-budgets)); the design expects run-rate trips, hard stops, exact runbooks and a short-lived Operate pre-release test (`docs/design/07-safeguards-and-drift.md:45-95,108-130`; `docs/design/09-delivery-and-operations.md:29,124-150`). **Fix:** assign a small runbook and live drill slice before first production Operate/send: pull, observe no new work, page independently, resume, and test hub outage and wallet overshoot with synthetic data.

14. **Major · `spec.md:89` ·** C10 expects a person to approve at phase-2 start, though the approval service and R3 action plane are phase 3/4 (`docs/design/13-roadmap.md:14-16`). Its fallback “published front door” quietly contradicts private `approvals` and the bot as sole public endpoint (`docs/design/02-architecture.md:53-61`; `docs/experience/06-web-pages.md:23-26`). **Fix:** split phase-2 page reachability, sign-in and failure-copy tests from later bound R2/R3 approvals; use a tested private access route. Public ingress needs a separate security, cost and architecture decision.

15. **Major · `spec.md:95,97,101,109` ·** “No other role” erases required mailbox, network, identity and billing administrators (`docs/design/09-delivery-and-operations.md:180-189`). “Licences the organisation already owns” invents adopter facts. Data-boundary/hub/runner choices have no default although the spec promises one. These break community and no-invention rules (`AGENTS.md:16-17,28`); the release also omits the cold stranger test (`AGENTS.md:26`). **Fix:** name request owners and lead times without asserting licences, mark high-impact choices as required rather than guessed, and gate the document release on a stranger read.

## What I would change first

1. Repair the dependency graph and stage truthful acceptance checks; no Phase 0 or 1a exit by relabelling a failure.
2. Lock down the mailbox grant and the agreement-specific bill path before promising a live digest.
3. Set a pilot safety/release gate, the stop drill and the minimal truthful Monday status view before production mail.

**Would I commit a team to this plan as it stands? No.**
