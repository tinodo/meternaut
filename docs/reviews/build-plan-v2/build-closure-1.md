## New defects

1. **Minor — `evaluation/c14/harness/runner.py:62-68` and `evaluation/c14/run.py:85-103`: `run.py run` does not save updated cumulative usage back to `results.json` when stopped before any arm call, and `reevaluate` (`runner.py:204-212`) does not re-check that the reviewer did not tamper with `review.json["claim"]` after the run.**
   - **Why wrong:** When `run.py report DIR` is run after a person sets `answers_read_by` and `answers_rest_on_the_claim` in `review.json` (`run.py:105-113`), `cmd_report` reads only `read_confirmation(directory)` from `review.json` and passes it to `reevaluate(results, ...)` without verifying that `review.json`'s `decision`, `reviewer`, or `claim` still match `results["review"]`. If someone edits `review.json` after the run (e.g., changing `decision` to `"pending"` or altering `claim`), `cmd_report` ignores that change and marks the run `Passed`.
   - **Fix:** In `cmd_report` (`run.py:107-112`) or `reevaluate` (`runner.py:204`), compare `review.json`'s `decision` and `claim` against `results["review"]` (or re-run `load_review`) and refuse to mark `passed: True` if `review.json` was modified inconsistently with `results.json`.

2. **Minor — `evaluation/c14/harness/cases.py:205-209`: `_amount_forms(value)` omits two-decimal formatting (`1168.00` / `1,168.00`) and non-integer comma formatting (`1,168.50`).**
   - **Why wrong:** For `monthly_waste_eur = 1168.0`, `_amount_forms` returns `["1168", "1,168"]`, and `re.search(rf"(?<![0-9.,]){re.escape(form)}(?![0-9])", text)` (`cases.py:225`) matches `"1168.00"` because `"."` is not in `(?![0-9])`. However, for a non-integer amount >= 1000 such as `1234.5` (`float(value).is_integer()` is `False`), `_amount_forms` returns only `["1234.5"]` and misses `"1,234.5"` and `"1,234.50"`.
   - **Fix:** In `_amount_forms` (`cases.py:205`), also include `f"{value:,.2f}"` and `f"{value:,.2f}".rstrip("0").rstrip(".")` so comma-formatted fractional amounts are caught.

3. **Minor — `tools/pilot-feasibility.py:52-56`: `SCOPE` regex omits legacy EA top-level `/providers/Microsoft.Billing/departments/{id}` and `/providers/Microsoft.Billing/enrollmentAccounts/{id}` scopes.**
   - **Why wrong:** On Microsoft Learn (`Generate Cost Details Report - Create Operation 2022-05-01`), the URI parameter table and sample requests (`GenerateCostDetailsReportByDepartmentsAndTimePeriod`, `GenerateCostDetailsReportByEnrollmentAccountsAndTimePeriod`) use `/providers/Microsoft.Billing/departments/{departmentId}` and `/providers/Microsoft.Billing/enrollmentAccounts/{enrollmentAccountId}` (in addition to the `/billingAccounts/{id}/...` paths used by the Query API).
   - **Fix:** Allow optional `/billingAccounts/[^/]+` before `/(departments|enrollmentAccounts)/[^/]+` in `SCOPE` (`pilot-feasibility.py:52-56`).
