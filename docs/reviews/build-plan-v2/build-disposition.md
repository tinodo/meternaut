# Build review 1: disposition

A reviewer on a third model family (gemini-4-argon) read what was built so far, against the brief in [brief-build.md](brief-build.md): the harness of check C14, the probe of check C13, their tests, the first CI and the Bicep templates for the early stages. The report is [build-review-1.md](build-review-1.md): 13 findings (4 Blockers, 7 Majors, 2 Minors), and the verdict was Release: NO. The reviewer found the API shapes, the pass numbers, the way the key stays out of the prompts, the handling of secrets and the action pins right. This record says what was done with each finding. Every one changed something, and the tests grew from 103 to 141.

| # | Finding (severity) | Verdict | What was done (where) |
|---|---|---|---|
| 1 | A real run can end above its spending cap: without prices the cap is never checked, the call that crosses the cap is made, and `propose` is counted apart from `run` (Blocker) | Accepted | A real run does not start without a cap, token prices, a reply limit and a call limit. The hub is told the reply limit, and before each call the guard refuses a call whose worst case (the cost so far, the prompt estimated generously, a full-length reply) could pass the cap. `run` starts from the calls and tokens that `propose` recorded. A cap without prices or a reply limit is an error (`harness/client.py`, `run.py`) |
| 2 | `run` exits 0 when the verdict is pending (Blocker) | Accepted | Exit 0 only when every pass condition holds; `report` works the verdict out again and has the same rule (`run.py`) |
| 3 | The probe can send the token to any host named by a `Location` header and can repeat a signed download link in an error (Blocker) | Accepted | The token goes only to management.azure.com and every other link must be https and gets no token; every message loses the query string of a link and any signature (`tools/pilot-feasibility.py`) |
| 4 | The file route misses the FOCUS cost columns and accepts a file with no resource or currency column (Blocker) | Accepted in part | FOCUS names are read (`BilledCost`, `ChargeCategory`, `PricingCategory`, `CommitmentDiscountName`, `ListCost`, `ListUnitPrice`, `x_EffectiveUnitPrice`); a file without a resource column, a currency column or a numeric cost is refused. Not adopted: a minimum share of lines with a resource id. The plan states no such number, so the record carries the share and a warning above one half, and a person decides |
| 5 | No paging of the Query API, no handling of "no content", "failed" or "no data", compressed parts (Major) | Accepted | Every page is followed (at most 50); 204, `Failed` and `NoDataFound` stop at once with a clear message; a gzip part is read instead of refused |
| 6 | The scope check refuses billing scopes that design 14 lists (Major) | Accepted | Invoice section, department, enrollment account and customer scopes are accepted |
| 7 | A hurried reviewer can make a C14 pass meaningless: a snapshot of one claim, a claim with the id of another, a changed claim marked accepted, no check that a person read the answers (Major) | Accepted in part | The smallest snapshot is a parameter (the template has five, the plan's starting value); the claim's id must be new and its mechanism must differ from the control's; `accepted` is refused when the claim differs from the draft and `edited` when it does not; the draft is checked for giving away a case when it is proposed; and the pass waits until a named person records in `review.json` that the updated answers rest on the claim. Not adopted: a bar on how many updated answers cite the claim; the report shows it, and the person's reading is the gate, as the plan says |
| 8 | The leak check is lexical and misses names and numbers (Major) | Accepted in part | A claim may not name a case (its id or a name-like value such as `shop-search`) or state the amount that the key gives for one. Not adopted: a check on every number in a case's facts, because numbers such as the hours of a month are legitimate in a claim |
| 9 | The control is matched on the length of its statement, not of what the finder sees; the case title is not shown (Major) | Accepted in part | The control is matched on its length in the prompt, within 30 %. The title is for the person reading the report and is the same for every arm, so it confounds nothing; the README says so |
| 10 | A documented `--self-test` does not exist; tests are missing for the stop test, propose without a cap, paging, failed reports and an off-host link (Major) | Accepted | The line is gone from the docstring, and tests were added for each case named |
| 11 | The anomaly alert wants UTC date-times, and the README leaves out that the creator must keep Reader (Major) | Accepted | The parameters say UTC times, and the README and the template say what Learn says: the alert is sent on the creator's access at the time, so a service principal creates it; at most five rules in a subscription; public cloud only |
| 12 | The budget's start date and the roles are not stated exactly (Minor) | Accepted | The start date is the first of a month, the current one or a later one; the roles are listed as Learn lists them |
| 13 | `infra/` is not linked from the README; `az` is started through a shell (Minor) | Accepted | The README links it; the probe resolves `az` with `shutil.which` and runs it without a shell (checked on Windows) |
