## 1. What the orchestrator found itself between the revision and the pass

Five revision agents applied Round 2 in parallel, each owning two or three documents. A large parallel revision has one characteristic failure: each owner is right inside its own files and the *seams* between files move. Before the pass was launched the orchestrator read every revision report, ran the lint and the cost model's `--check`, grepped for the stale phrases that Round 2 retired, and checked the seams. These were found and fixed first, so that the third-pass reviewers did not spend their attention on them.

## 2. T-A — the authority chain and the leaf-call rule

**Verdict of the reviewer:** "Unsafe for estate-changing action … Block execution until independent controls and fault tests pass." **28 findings: 16 Critical, 12 Major.** ADR-07 **Disagree** (high), ADR-08 **Disagree** (high), ADR-33 **Agree with changes** (high). That verdict is consistent with the design's own stance — nothing changes an estate before the spikes S-ID-1, S-ID-3 and S-ACT-1 pass — but it is a harder reading of *the text* than Round 2 reached, and most of its findings are real.

**Orchestrator's checks.** All 27 repository quotations of 30 characters or more are verbatim at `6694d15` (the reviewer's own validation said the same of its 28). Of the platform facts the findings rest on, the orchestrator re-read on Learn today the four that decide a finding: **a delegated subnet cannot host a private endpoint** ("Can't be used with a private endpoint if the subnet is delegated.") while a workload-profiles Container Apps environment must be delegated ("You must delegate your subnet to `Microsoft.App/environments`.") — so `stchain`'s private endpoint could not have been deployed in `snet-exec`; **internal ingress is reachable only from the same Container Apps environment** ("directly reachable only from within the same Container Apps environment"; a request to the internal load balancer for such an app "returns an HTTP 404 response") — so the Policy service, Approval service, Audit Writer and Estate service, called from other environments, needed VNet ingress; **instance ids** ("They must be between 1 and 100 characters", no `/ \ # ?`, not starting with `@`); and **the federation direction** (Learn: "configure a Microsoft Entra application to trust a managed identity"). Each was true. The rest (ID-token lifetime, Cosmos DB's container-level RBAC, no dead-lettering in Storage queues, the Invocations adapter only echoing the id) agrees with what the documents already cite.

**Decisions.** Each finding is dispositioned below; the decisions are recorded where they landed (last column) and in the *Third pass* lines of ADR-07, ADR-08 and ADR-33.

**Not adopted as proposed, and why.** A page-signed receipt for the decision (TA-01) would add a seventh signing party and vault; binding the decision into the nonce gets the same property with the keys we already have. One container per writer (TA-03, TA-04) would triple the operational containers for a property that item-level signatures give and that the ledger already uses. "Time-limited job authority" (TA-06) is replaced by removing the start right in production and adding the lock, because a compromised pipeline can ignore any control that it itself enforces; the residual is stated instead.

## 3. T-B — the spend budget and the contract × environment model

**Verdict of the reviewer:** the reservation-as-budget redesign is "the right shape, and the generated block of 12 is arithmetically honest", but "not yet a budget that *holds*". **5 findings: 3 Major, 2 Minor.** ADR-26 **Agree with changes** (0.7), ADR-06 **Agree with changes** (0.8).

**Orchestrator's checks.** The four quotations that no longer exist in the working tree were verbatim at `6694d15` (the sentences were corrected after the review). The reviewer's five re-derivations from the snapshot were reproduced independently for four meters (AI Search Basic €0.088877/h; the private endpoint €0.0088/h; the Flex always-ready baseline €4e-06 per GB-second; Content Safety €0.329989 per 1,000 records). That check also found something the reviewer did not: **four per-second meters in the snapshot carry the `eur-precision-loss` flag** — their euro value has one significant digit, about 14 % above the dollar price at the snapshot's rate. The model uses the listed euro value, so those lines err high; 12 §1 now says so. The reviewer's platform claim about **priority processing** was verified on Learn: "`service_tier = priority` means the request uses the priority processing service tier", a body `priority` on a deployment whose default is standard "is processed by Priority processing", and "The service currently doesn't support regional standard deployments and EU datazone standard deployments" — so the EU pools are not exposed but the Global and Flex pools are.

## 5. What the review record shows

Three rounds, nine models, 132 findings in the first two rounds and 33 in the third (28 + 5). The pattern that repeats is worth keeping: each round's *fixes* are where the next round's findings live — a signer that could also start the runner (Round 2) became, in the third pass, a set of markers that any identity with container access could forge, a private endpoint that could not be deployed and an ingress that could not carry the calls. The remedy that worked was the same each time: read the platform's own words before believing a sentence of the design, and make every "cannot" name the mechanism that stops it.
