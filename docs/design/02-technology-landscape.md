# Design 02 — Technology landscape

> **What this answers:** *What does the Microsoft AI ecosystem offer today — as of 2026-10-31 — and which of it does this design adopt, hold behind a switch, evaluate or leave alone?* The operator supplied a year of updates (817 rows, 31 October 2025 to 31 October 2026); this document is the verdict on all of them, and the evidence behind every verdict is in the research files it links. Part of the [design](README.md).

---

## 1. How the landscape was built

1. **Every one of the 817 updates was triaged exactly once**, by eight parallel research agents, each reading a slice of about 100 rows and *following the links* to Learn pages, specifications, release notes and the Release Communications API (the Azure Updates pages are script-rendered shells and return no text). Each row got a disposition; related rows were merged into **267 clusters** with a status, a fit, a note on cost or security, and sources.
2. **Five core studies** went deeper where the design needed precision: the [Citadel framework](research/citadel.md), [Foundry Agent Service, models, knowledge and memory](research/foundry-agent-service.md), [Foundry governance, identity, networking, evaluation and the Agent Framework](research/foundry-governance-and-framework.md), [security and compliance](research/security-and-compliance.md) and an [options analysis](research/options-analysis.md) of hosting, data, operations and channels. A reproducible [price snapshot](research/prices.md) feeds the [cost model](12-cost-and-finops.md).
3. **The register is generated, never hand-edited:** `tools/merge-features.py` merges the eight digests into the [feature register](research/feature-register.md) and checks that every row is covered once.
4. **Evidence rules.** The **page wins** over the attachment when they disagree (the research names each clash). Every status carries its date and its source. A claim that rests on the attachment alone is marked *unverified*. Prices are **indicative**, from the Retail Prices API on 2026-10-31.

## 2. The twelve hypotheses, judged

The research brief began with twelve hypotheses about the platform. This is what the evidence did to each.

| # | Hypothesis | Verdict | What changed | Answered in |
|---|---|---|---|---|
| **H1** | Foundry Agent Service, with Agent Framework workflows | **Confirmed, with two edits** | Foundry visual workflows retire **1 Dec 2026**; hosted agents are generally available; prompt agents leave the critical path (reaching the gateway needs a connection limited to Chat Completions, while the strongest models need Responses for tool calls); orchestration moves *out* of any agent into a deterministic spine, which after Round 1 is **Durable Functions on Flex Consumption** rather than our own checkpoint store, with the Agent Framework inside the leaves | [05](05-agents-and-orchestration.md), [ADR-01](13-decisions.md#adr-01-a-deterministic-spine-calls-agentic-leaves), [ADR-33](13-decisions.md#adr-33-the-spine-is-durable-functions-on-flex-consumption-calling-leaves-through-the-hub) |
| **H2** | Everything through the Citadel hub | **Confirmed, with a split** | "AI gateway" now means three things; Citadel is a **single-maintainer sample**, not a service; hosted agents call the hub from code; a **bypass register** lists twelve paths that skip it (the twelfth is the spine's own call to a leaf) and how each is closed | [04](04-landing-zone-and-citadel.md), [ADR-02](13-decisions.md#adr-02-the-gateway-is-the-citadel-governance-hub-on-api-management) |
| **H3** | Private networking only | **Partly** | five named public-ingress or non-private exceptions (the fifth is the approval web page); managed VNet is a one-way door with a managed-firewall charge; the standard setup brings its own stores (five Cosmos DB containers per project), while a BYO-VNet can also use platform-managed data, so networking alone does not force them (S-NET-2); Purview's Foundry integration does not support network isolation | [04 §6–7](04-landing-zone-and-citadel.md#6-network), [07 §7](07-security-architecture.md#7-network-and-the-short-list-of-exceptions) |
| **H4** | Two planes with just-in-time identity | **Holds; the mechanism changed** | PIM cannot make a managed identity eligible, so a broker creates and removes a scoped role assignment, and only after *itself* verifying the Policy permit, the Approval service's signed record, that record's entry in the ledger and, for a person's approval, that person's Entra-signed token; the event-driven runner verifies again before it acts and the Approval service starts nothing. *No single credential completes a change that needs a person's web-page approval.* A compromised Approval service cannot start a job, fabricate a permit or fabricate a person's Entra-signed token. On the card path (reversible Moves of the lowest class only) the proof is the bot channel's assertion, which a compromised Approval service can fabricate; that is why the path ends at that class. A compromised Approval and Policy service can approve within an autonomy credential's constraints, which the broker and the runner check against the credential itself. A compromised broker can grant constrained Move roles without a lease; a compromised release pipeline can run code as a runner identity while it holds a role. Each is bounded and detected as stated in [07 §3.3](07-security-architecture.md#33-the-execution-identity-just-in-time-without-pim). | [07 §3.3](07-security-architecture.md#33-the-execution-identity-just-in-time-without-pim), [07 §4](07-security-architecture.md#4-approvals-that-cannot-be-forged-or-reused), [ADR-07](13-decisions.md#adr-07-execution-identities-are-granted-just-in-time-by-a-broker-on-a-signed-approval) |
| **H5** | Git plus a search index plus one serverless store; columnar files and an embedded engine | **Confirmed** | Cosmos DB serverless chosen with Azure SQL as fallback; the embedded engine is a **recorded exception to C1**, with an owner and an expiry, kept only if S-DATA-1 shows it beats the Microsoft-only options on measured simplicity and cost; Foundry Memory not used | [06 §7](06-data-and-knowledge.md#7-the-physical-stores), [ADR-12](13-decisions.md#adr-12-the-operational-store-is-cosmos-db-serverless), [ADR-13](13-decisions.md#adr-13-cost-analytics-is-parquet-and-an-embedded-engine-in-a-job) |
| **H6** | Scale to zero | **Confirmed, with a ledger of exceptions** | private networking forces fixed meters (private endpoints, a Premium registry, search units, the hub's usage pipeline) and the Durable Functions spine needs one always-ready instance; SRE Agent bills always-on | [12](12-cost-and-finops.md), [options analysis §1.2](research/options-analysis.md) |
| **H7** | Models tiered by role, budgets in the contract | **Confirmed, sharpened** | the **EU Data Zone premium is about +20 %** on the GPT-6 family (about +10 % on earlier meters; no flat rule); Flex (−50 %, Global only) serves delay-tolerant public work and Batch is deferred until it has its own adapter; the router's pool drifts under a fixed label; Claude has no EU Data Zone option and its hosting version is pinned | [05 §6](05-agents-and-orchestration.md#6-models-and-the-alias-map), [ADR-09](13-decisions.md#adr-09-models-are-aliases-and-the-data-class-chooses-the-deployment-type) |
| **H8** | Safety in layers | **Holds, with gaps** | agent guardrails are preview and *override* the model's; document-attack screening is off by default; agent-level Defender protection moved behind a licence; hosted-agent egress rules are a preview whose Learn page says preview features "are not intended to be used in production or in a live operating environment" ([Learn](https://learn.microsoft.com/azure/foundry/agents/how-to/add-hosted-agent-guardrails#network-egress-controls-preview)); Foundry guardrails moderate only the first 1,000 characters of text ([Learn, service limits](https://learn.microsoft.com/azure/ai-services/content-safety/region-availability#service-limits)); on the Invocations protocol a guardrail policy without its moderation setting is inert, and the hub's built-in content-safety policy screens MCP and A2A responses (S-SEC-2, S-GW-4) | [07 §5](07-security-architecture.md#5-defence-against-prompt-injection-in-nine-layers), [ADR-19](13-decisions.md#adr-19-nine-layers-against-injection-with-a-deterministic-gate) |
| **H9** | An identity and a sponsor per agent; authenticated approvals | **Holds** | Entra Agent ID is free and generally available; Conditional Access for agents needs a licence; the primary audit trail must be ours; fifteen hosted-agent identities serve fourteen roles in eleven contract groups; a person's approval is an Entra-signed token whose nonce binds the request, the target and the decision, and the approve sign-in starts only from a click on **Approve** (a decline starts none); the nonce proves that the token was minted for that request, not that a click preceded it or what the person saw, so the page's display is a stated residual; Conditional Access on the approval app (authentication strength: multifactor; it needs Entra P1) enforces the second factor, so where `auth_time` and `amr` cannot be had the web page is not used for irreversible Moves, purchases or credential grants; on the card path (reversible Moves of the lowest class only) the proof is the bot channel's assertion, which a compromised Approval service can fabricate, and that is why the path ends at that class | [07 §3–4](07-security-architecture.md#3-identity), [ADR-06](13-decisions.md#adr-06-an-entra-agent-identity-per-agent-and-eleven-contract-groups) |
| **H10** | Teams and e-mail first; voice off | **Confirmed** | Foundry's publishing route is public and conversational; approvals need our own adapter (C#, for typing and shared contracts with the Approval service; Python's SDK also has card actions), but a Teams card carries no end-to-end Entra token bound to the target, so it approves in place only for the lowest class of reversible Move and hands every other class to the web approval page: on the card path the proof is the bot channel's assertion, which a compromised Approval service can fabricate, and that is why the path ends at that class; Voice Live is generally available with Agent Service but voice agents are preview | [ADR-17](13-decisions.md#adr-17-teams-through-our-own-adapter-e-mail-through-graph-voice-off) |
| **H11** | Drift controlled at every layer | **Confirmed, made concrete** | hosted agents are data-plane objects that Bicep cannot guard; the platform changes under unchanged labels; so a drift controller of deterministic detectors | [09](09-safeguards-and-drift-controls.md), [ADR-21](13-decisions.md#adr-21-drift-is-controlled-by-deterministic-detectors-and-a-preview-register) |
| **H12** | Bicep, stacks, GitHub Actions, gated releases | **Confirmed** | stack limits (five excluded principals; resource-group deletion bypass; moving a managed resource out of a stack removes its protection); a GitHub environment needs only one of several reviewers, so the two-person rule is a required check (S-DEL-2); `azd`'s agent extension is beta; no module for sandboxes or agent versions; Deployment Environments retires | [11](11-delivery-and-operations.md), [ADR-23](13-decisions.md#adr-23-bicep-with-verified-modules-deployment-stacks-and-github-actions) |

## 4. Findings that change the design

The twenty that moved a decision, ranked by how much they moved it. Each is evidenced in the digests and the core studies.

| # | Finding | Effect on the design |
|---|---|---|
| 1 | **Foundry visual workflows retire 1 Dec 2026**; hosted agents are generally available (June 2026) | the spine is Durable Functions (C#) calling hosted-agent leaves through the hub; the Agent Framework runs inside the leaves |
| 2 | **The Citadel hub is a sample**, built on API Management, with a ≈ €320 a month always-on usage pipeline | fork and pin; share or trim; contracts as data |
| 3 | **Prompt agents reach a gateway only through a Chat Completions connection**; the strongest models need Responses for tool calls | hosted agents call the hub from code |
| 4 | **PIM cannot make service principals or managed identities eligible** | a broker creates a scoped role assignment per Move, only after verifying the approval itself (the permit, the signed record and a person's token) |
| 5 | **EU Data Zone is a price tier** (about +20 % on the GPT-6 family, about +10 % on earlier meters); Flex and Batch are cheaper but Global | routing by data class at the hub; prices by exact meter, never by a flat percentage |
| 6 | **The router's pool changes under an unchanged version label** | aliases, pins, a behavioural fingerprint, an exam on change |
| 7 | **Agent guardrails are preview and override the model's**; document-attack screening is off by default | layered defence with deterministic layers carrying the weight |
| 8 | **Defender for agents moved behind an Agent 365 licence**; Defender for AI Services is token-metered | optional modules with fallbacks; our own detections |
| 9 | **Purview's Foundry integration does not support network isolation** | our own append-only audit ledger |
| 10 | **Network choices are one-way**: BYO-VNet at account creation; managed VNet creates a firewall | a pre-flight check; BYO-VNet chosen |
| 11 | **Sweden Central is the only candidate region (of West Europe, North Europe and Sweden Central) in every list that matters**; serverless search is also offered in Denmark East and Poland Central, and Learn flags Sweden Central as "in high demand, which prevents the creation of new search services" | primary region; the intersection is re-run when a list changes; the Search service is created on day zero and may sit in another EU region ([14 §2](14-next-phases.md#2-assumptions-to-confirm-in-the-first-week)) |
| 12 | **Hosted-agent versions are data-plane objects** | a drift controller; immutable versions; manifests |
| 13 | **Azure Deployment Environments and Lab Services retire** (22 Feb and 28 Jun 2027) | the Lab is vending, stacks and a reaper |
| 14 | **Budgets alert on old data and stop nothing**; no spending limit on EA, MCA or pay-as-you-go | the hub is the cap; Lab caps are structural |
| 15 | **SRE Agent bills 4 units an hour always-on** | off by default |
| 16 | **A Teams-published agent needs a public, source-filtered route**; card actions exist in the .NET, JavaScript and Python Agents SDKs | our own adapter, in C# for typing and shared contracts; exceptions X1 and X5 |
| 17 | **Private networking forces fixed meters** on services that are otherwise pay-per-use | a ledger of always-on meters in [12](12-cost-and-finops.md) |
| 18 | **Embedded analytics is the simplest zero-standing-compute option**, and it is open-source rather than Microsoft; Synapse serverless SQL also reserves no idle compute | a recorded exception to C1 with an owner and an expiry, until S-DATA-1 measures both |
| 19 | **Opaque run codes made experiments exact** (100 % against 68 % for parameters in prompts) | the Experimenter passes codes, not parameters |
| 20 | **The release feed and the Learn MCP server are keyless sources** | the change radar is cheap and structured |

## 5. Currency: the landscape is a living document

A snapshot ages in weeks: during this study alone, labels disagreed between pages (hosted agents: preview or generally available; Routines; Voice Live; Astra's data zone) and the research names each clash. Round 1 added two more clashes (the status of Container Apps Sandboxes, and whether a Search service may sit outside the Foundry resource's region); Round 2 added two that the rule settles (the Durable Task Scheduler's Consumption SKU, where the release record says generally available and a Learn page still says preview, so the record wins; and orchestration versioning, in preview on the release record with no label on Learn, so it is held as preview). **A status on which sources conflict is held at the weaker label** — preview, not generally available, and an unproven placement rather than a permitted one — until a first-party record settles it. The register therefore has an owner and a clock: **the Scholar's change radar watches the release feed for everything in it** ([09 DR-9](09-safeguards-and-drift-controls.md#22-drift-under-us)), a status that expires after thirty days is flagged for re-verification, and a change to an ADOPT or ADOPT-PREVIEW row opens an item on the Agenda. The dates of known retirements are in the dependency register ([09 §5](09-safeguards-and-drift-controls.md#5-the-preview-register-and-the-dependency-register)).

## 6. What this document does not claim

Dispositions are **fit for this design**, not statements about product quality. Statuses are those of the day and the page cited. Where the research could not confirm a fact (a price that renders as a dash, a region list that did not load, a status absent from a page), it says so, and the design either avoids depending on it or turns it into a **spike** ([14 §3](14-next-phases.md#3-spike-register)).
