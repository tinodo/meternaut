## 1. What is being designed

**Azure Cost in Action** is an AI-driven, human-in-the-loop Azure cost-optimisation system, imagined as *a scientist for Azure's economics*. Five faculties — **STUDY** (learn how Azure services bill), **SURVEY** (understand an estate and its owners), **TEST** (investigate; experiment in a sandbox Lab), **ACT** (work with people; carry out approved changes), **GROW** (score itself, sit exams, share knowledge) — work around one shared memory. Read the [north star](../../01-north-star.md) (the first 120 lines are enough) and, only when needed, the deep dives [02](../../02-learning-azure.md) to [12](../../12-press-release-from-the-future.md). It is **not** a chatbot and **not** a rulebook: cooperating agents do the work, people approve changes.

The cast (13 agents): Scholar, Cartographer, Surveyor, Detective, Skeptic, Experimenter, Economist, Diplomat, Engineer, Auditor, Examiner (with its adversarial twin, the Forger), Librarian, Conductor. Other parts: the **Atlas** (claims about how Azure charges, each with receipts), the **Estate Model** and **Lesson Book**, the **Lab** (sandbox subscriptions where agents run billing experiments), **Moves** (tested change recipes, run only after human approval; purchases need two named approvers), the **Terrarium** and **Exam** (synthetic estates with planted waste; independent scoring), the channels (Teams cards, email; optionally voice, SMS, an avatar in meetings) and the **Commons** (the open-source half of the knowledge).

## 3. Working hypotheses — to be tested, not decisions

| # | Hypothesis |
|---|---|
| H1 | The agents run on **Foundry Agent Service** (declarative prompt agents where simple, **hosted agents** with Agent Framework code where a role needs custom tools or long loops), orchestrated by **Microsoft Agent Framework workflows** (graph, checkpointing, human-in-the-loop requests). |
| H2 | Every model, tool (MCP) and agent (A2A) call goes through the **Citadel Governance Hub** (the APIM-based AI gateway) under **access contracts** — one per agent group and environment — and our own tools and agents are exposed through **publish contracts**. |
| H3 | The solution is a **spoke**: an *AI Landing Zone for Microsoft Foundry* deployment, private networking only, inside the operator's landing zone. |
| H4 | Two planes. The **reasoning plane** (agents) holds read-only Azure identities. The **execution plane** (the Move runner) holds nothing until a recorded human approval activates a scoped, short-lived identity for that one Move. |
| H5 | Memory: the **Atlas** is Git (open) plus a search index; the Estate Model, Lesson Book, Experiment Ledger and approvals sit in **one serverless operational database**; cost data is columnar files in object storage queried by an embedded engine in scale-to-zero jobs — with **no standing analytics cluster**. (To be compared with the alternatives.) |
| H6 | **Scale to zero** by default; always-on components only where latency demands them. |
| H7 | Models are **tiered by role**: small cheap models for high-volume detection and triage, reasoning models for Detective, Skeptic and Economist, batch for nightly consolidation, embeddings for retrieval; a model router where it saves money; caching at the gateway; every agent has a token budget in its contract. |
| H8 | AI safety in layers: Foundry guardrails (prompt-injection shields, groundedness, task adherence, PII), gateway content-safety policies, external text treated as data and never as instructions, scheduled red teaming. |
| H9 | Identity: every agent has its **own agent identity** and a named human sponsor; least-privilege RBAC; Conditional Access; human approvals are authenticated actions in an append-only record. |
| H10 | Channels: Teams (Adaptive Cards) and email first; voice, SMS and the avatar meeting participant are optional modules, **off by default** for cost. |
| H11 | Drift is controlled at every layer: Deployment Stacks with deny settings, Azure Policy, pinned model/prompt/Move versions, continuous evaluation on production traces, regression exams on any change, quotas and budgets at the gateway — and the system watches its own estate with its own agents. |
| H12 | Delivery: Bicep (Azure Verified Modules), Deployment Stacks, GitHub Actions with OIDC, dev → test → prod, every release gated by evaluation thresholds and security scans. |

## 4. Vocabularies and rules

**Status** (as of today, from the page): `GA` · `Public preview` · `Private preview` · `Retiring (date)` · `Retired` · `Not stated`. Always give the date the page gives. **Disposition**:

| Code | Meaning |
|---|---|
| `ADOPT` | use it in the design; generally available and a good fit |
| `ADOPT-PREVIEW` | use it behind a switch, with a generally available fallback named |
| `EVALUATE` | plausible fit; needs a test or a cost check before a decision |
| `WATCH` | interesting, not needed for phase 1 |
