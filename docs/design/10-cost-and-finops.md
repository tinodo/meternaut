# Cost and FinOps

**What this document answers.** What the system costs to run at three scales; what it pays when nobody is using it; what moves the cost; what it must save to pay for itself; and what the numbers leave out.

## How to read the numbers

Every figure in the block below is generated by `tools/cost-model.py` from a price snapshot (Azure Retail Prices API, euro, Sweden Central) and from seeded volumes: calls per case, tokens per call, minutes per session. The prices are real list prices. The volumes are **seeds**, replaced by measurement in proof point P10 ([roadmap](13-roadmap.md)). The three scenarios are sizing parameters, not forecasts. `python tools/cost-model.py --update-doc docs/design/10-cost-and-finops.md` regenerates the block and `--check` fails when it is stale.

## What the numbers say

- **The plumbing costs more than the thinking at small scale.** At Pilot size the idle floor — AI Search Basic, private endpoints, the always-ready Functions instance that Learn recommends for Durable Functions, the Durable state storage — is most of the Operate profile; production tokens are small. At Enterprise size production tokens and logging dominate. Cost per case falls as the floor is spread over more cases.
- **Evaluation is the largest variable cost of the dev environment**, and a large share of all token spend at Pilot size. It is kept small by running suites on change rather than continuously, on the Flex tier where it is available, with sampled production scoring ([testing and evaluation](08-testing-and-evaluation.md)). Flex is preview and applies to Global Standard deployments of listed models: it is about half the Global Standard token price, and the sensitivity table shows the cost without it.
- **The data boundary is a policy choice with a price.** Data Zone deployment for estate data costs about a fifth more per token than Global Standard on current models; the sensitivity table shows the effect. Public documents and synthetic data use Global Standard.
- **The hub is shared platform cost.** It is not in the totals. An organisation without a hub pays for the accelerator; the last sensitivity row shows that figure, and most of it is the hub's always-on usage pipeline, which a fork can replace with log queries ([architecture](02-architecture.md)).
- **Break-even is a small share of spend.** The system pays for itself if it finds and verifies a small fraction of the spend it manages; the headline gives the share for each scenario.

## The levers

| Lever | What it does | What it trades |
|---|---|---|
| Scale to zero | Functions, Cosmos DB serverless and hosted agents bill only while in use | Cold starts; the one always-ready instance Learn recommends for Durable Functions is the exception, and the sensitivity shows what it costs |
| Detectors first | Cheap compiled checks nominate leads; the model works on novel or ambiguous cases | Detectors need back-testing, shadow runs and expiry |
| Small model first | `triage` handles volume; `reason` is escalated on objective signals | Needs evaluation to set the thresholds |
| Flex and Batch | About half price for study, evaluation and consolidation | Flex is preview; latency; Global processing only |
| Prompt caching | Stable prefixes are read at a fraction of the input price | Cache writes cost more; breakpoints only on prefixes reused several times a session |
| Evaluation on change plus sampling | Suites run when something changes, not all the time | Slower detection of slow drift; covered by sampled production scoring |
| Platform-managed Foundry data | Removes Foundry's own Cosmos DB and Storage and two private endpoints | Agent data is not in the organisation's own resources (a parameter turns it on) |
| One search service, one vault, no registry | Fewer fixed meters | Shared blast radius for the search index; mitigated by scoped roles |
| Log Analytics table plans | Bulky tables on cheaper plans | Basic and auxiliary plans limit queries |
| Reuse the organisation's hub | No second gateway | Depends on the hub's roadmap |

## What the numbers leave out

- **People's time.** Owner time on cases and reviewer time on Atlas pull requests are given in hours, not money.
- **Licences.** Microsoft Entra P1 or P2, Microsoft 365, Agent 365 and Defender plans are the organisation's own ([goals and scope](01-goals-and-scope.md)); Defender for AI Services appears only as a sensitivity. Mail sent through Microsoft Graph has no per-message charge.
- **Foundry's own evaluation meters.** Safety evaluations, red-team runs and agent-playground evaluations bill on their own meter; the model counts tokens only ([testing and evaluation](08-testing-and-evaluation.md)).
- **A deployment runner inside the network.** Deploying to a private Foundry account needs a runner that can reach it ([delivery and operations](09-delivery-and-operations.md)); its cost depends on the organisation's choice.
- **A second region.** Recovery is by redeployment in phase 1; a standing second region is phase 5.
- **Free grants** (Functions, Log Analytics, Key Vault, the semantic ranker) are applied; taxes, support plans and negotiated discounts are not.
- **Quoted figures.** A few figures are not in the price API and are quoted with their source at the end of the block; one of them (PII detection) is marked UNVERIFIED.
- **Model seeds.** Calls per case and tokens per call are placeholders until P10.

## The solution watches its own bill

The platform is onboarded as one more estate. It reads its own cost the way it reads any other: Azure budgets and anomaly alerts raise a warning, and because budgets only alert, the hard stops are the hub's token quotas per contract and a run-rate trip in the workflows that flips the global kill switch ([safeguards and drift](07-safeguards-and-drift.md)). Cost per case is computed from hub logs, so a regression in tokens per case shows up as drift ([technology register](11-technology-register.md) lists the pricing behaviour of each service).
