## 3. Findings that change the design

- **Foundry workflows retire on 2026-12-01.** The visual designer and in-portal runs end; hosted agents are not supported in the designer; Routines cannot target workflow agents. Microsoft's migration table: Agent Framework (recommended; supports declarative YAML as well as code, and the result runs as a hosted agent), Azure Logic Apps (visual designer), A2A (simple hand-offs). H1's orchestration is therefore Agent Framework workflows in a hosted agent; this is a confirmation, not a change, but "Foundry workflow agents" must be struck from any option list. Sources: Learn workflow page, Logic Apps blog, Routines blog.
- **A hosted agent is not an ARM resource.** Foundry account, project and connections are ARM (`Microsoft.CognitiveServices/accounts/projects/...`), but the agent is a data-plane object (`Microsoft.Foundry/agents@v1`; AzAPI `azapi_data_plane_resource`, SDK, REST or azd `azure.ai.agent`). Deployment Stacks deny settings and Bicep drift control (H11, H12) cannot cover agent definitions. Use azd or pipeline deploys, evaluation gates and explicit version pinning: default routing follows the latest version, so pin the candidate's version before testing and promote by changing a pointer (for example an App Configuration value). Versions are immutable and capped at 1,000 per agent (the cap error is terminal), so the pipeline must prune. The azd agents extension is still beta (rules tightened 2026-09-30).
- **AI Gateway is now a separate product (preview).** Resource type `Microsoft.ApiManagement/aigateways`; East US 2 and Sweden Central only; Learn calls it "the primary path for Microsoft's latest AI gateway capabilities", while APIM's AI gateway "remains available and supported". Agent 365 per-tool blocking, tool activity observability and tool threat protection need this tier; APIM v2 tiers get server-level block only. Citadel (APIM-based) stays the mandated path, but A1 must record the exit and a GA decision gate.
- **The Copilot harness sits outside the gateway.** It does not support bring-your-own-model (the Foundry feature that routes an agent's model calls through APIM or another gateway) and has no Foundry Memory, so H2 ("every model call through Citadel") cannot hold for harness agents. Its request fields (`service_tier`, `max_output_tokens`, caching keys) are harness-managed; egress control is a preview RAI-policy network rule; billing starts 2026-12-01 ($0.0994 per vCPU-hour, $0.0118 per GiB-hour). Use hosted agents for roles that must be governed per contract (your code picks the endpoint, so calls can target the gateway; egress lockdown is still preview); harness only by explicit exception.
- **EU residency now costs more.** From 2026-09-01 EU Data Zone is +20% over Global (was +11%) for models launched on or after that date; Regional in West or North Europe +50%, Sweden or Germany +30%; PTU rises for everyone. GPT-6.1 Terra: Global $1.00/$5.00, EU Data Zone $1.20/$6.00 per 1M tokens. Cost model: default Data Zone EU; Global only for data without residency needs.
- **Flex processing (preview, 50% discount) needs a Global Standard deployment**, is chosen per request (`service_tier: flex`), returns 429 when capacity is short and has no SLA; Priority Processing is n/a for Astra, 6.1 Sol and Luna. Flex and Batch therefore conflict with an EU-residency default for anything that carries personal or estate data; keep them for public, non-personal work (for example Atlas evaluation).
- **Claude is not on the EU-resident path.** Azure-hosted Claude offers Global Standard and Data Zone (US) only; Anthropic-hosted is Global only and may process outside Azure. Anthropic is seller and independent processor; billing is Claude Consumption Units via Marketplace (not Foundry token meters). Keep Claude out of H7's default tiers.
- **GPT-6 gives a very cheap triage tier.** Luna $0.10 in / $0.50 out per 1M tokens (Global), cached $0.01, available in EU Data Zone; the Decisions API (GA) runs on Luna and returns scores or choices instead of text. Astra is US Data Zone only. Terra's price table adds a separate cache-write rate (1.25× input) beside input, cached input and output; the SRE Agent AAU table prices cache writes too, so the Atlas token-meter model needs that dimension.
- **Routines are GA** (timer, cron schedule, GitHub issue, Teams channel message → one agent, agent identity by default). This can replace a scheduler for the Learning clock; it cannot react to Cost Management exports or Event Grid.
- **Teams delivery from hosted agents runs on the Activity protocol.** An agent published to Teams or Microsoft 365 on Responses is bridged to Activity automatically; a native Activity handler gives Adaptive Card actions and proactive messages, but needs the personal app installed and the conversation registered, and the destination should be fixed in code (the model never picks a recipient). Fits H10's Teams-first channel; the approval record stays ours. Sources: hosted-agents Learn page, September roundup.
- **Hosted-agent long-running resilience: GA announced, docs lag.** The devblog (2026-10-28) says GA "this week"; the Learn page (updated 2026-09-10), the September roundup and series part 1 (2026-10-26, which also lists the state store and network egress controls as preview) say preview. Treat as AP until the docs change. Recovery re-enters the handler from the start, so our own checkpoints and idempotency keys remain mandatory. Sources: harness devblog, Learn resilience page, https://techcommunity.microsoft.com/t5/microsoft-foundry-blog/global-enterprise-multi-agent-systems-in-production-design-and/ba-p/4564913.
- **Several H8 safeguards were still preview on 2026-10-26:** tool-call and tool-response intervention points, spotlighting, Task Adherence, Defender protection for Foundry agents, document-level access in AI Search, network egress controls. Mark each AP and keep the gateway's content-safety and prompt-shield policies as the GA layer. Source: https://techcommunity.microsoft.com/t5/microsoft-foundry-blog/global-enterprise-multi-agent-systems-in-production-design-and/ba-p/4564913.
- **Hosted agents validate H6 for human-in-the-loop.** Idle sessions are deprovisioned with state persisted and restored on the same session ID; retained up to 30 days; waiting for an approval costs nothing; an idle session does not count against the concurrent-session quota (2,000 in Sweden Central, 1,000 elsewhere, per subscription and region). Active compute is billed per vCPU and GiB hour.
- **Azure MCP Server 3.0 is GA** with Advisor cost tools (ranked by estimated annual savings), VM and VMSS comparison and Terraform/AVM tools; the apply tool returns IaC rules, not changes. Security stance to copy: tool filtering is not authorization, telemetry text is untrusted input (a log line can carry an instruction), read-only identities.
- **Evaluation and retrieval have measured cost levers.** Judge caching (≈70% of tokens, automatic), composite evaluators (−61 to −71% input; preview), `auto` retrieval effort (preview; $13.82 to $9.03 per 1,000 queries). Add to the H7 token-budget model. Tool Search is not a latency win (+43% p50 at 50 tools in one lab) but cuts input tokens.
- **SRE Agent has a fixed meter.** 4 AAU per agent-hour from creation until deletion, plus token-based active flow (GPT-6 Sol: 40 AAU input and 200 AAU output per 1M tokens); hitting the monthly cap disables chat and actions. New customers get up to 3 agents with no always-on charge for 30 days. This conflicts with H6 unless the agent is optional or created on demand.
- **Claude billing changed the cost data.** New CCU deployments attach to the Foundry account (`ResourceId`, tags) without project attribution; older deployments keep per-model meters. Seed an Atlas claim and test cost-ingestion mappings.
- **Retirements to avoid (fetched):** Foundry classic agents and their tools retire 2027-03-31; stored completions stopped 2026-10-15. Build only on the new agents and the Responses API.
- **Incidental, outside my slice: Azure AI Search Serverless (preview).** Consumption-based (Compute Units plus indexed GB), billing since 2026-09-13, no SLA, region-limited; not supported: index aliases, debug sessions, private networking for indexers, Shared Private Link ("no planned support"). A scale-to-zero candidate for H5/H6 that needs a check against H3 (A5). Source: https://learn.microsoft.com/azure/search/search-sku-tier.
- **Monthly "Microsoft FinOps News" is a ready-made Scholar feed.** The September 2026 edition carries the EU Data Zone price change, management-group-scoped savings plan and reservation recommendations (new), the SRE Agent 30-day trial and the Flex preview.
- **In-database model calls bypass the app tier (inference).** PostgreSQL `azure_ai` calls Foundry with the server's own managed identity; unless pointed at the gateway they escape per-agent contracts and quotas. Decide in A5 and A1 before choosing PostgreSQL for the operational store.
